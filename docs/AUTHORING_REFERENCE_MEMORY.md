# 연구개발 문서 작성 기준 — 사용자 합의 기억

저장일: 2026-09-25

## 사용자가 요청한 기준

각 레퍼런스에서 과제 내용에 따라 소주제를 어떤 순서와 논리로 작성했는지 참고하여, 사용자가 연구내용을 주면 해당 양식에 맞는 본문을 작성한다. 일반적인 공통 작성요령만 반복하지 않는다. 이 문서는 프로젝트에 남기는 지속적인 작업 기준이며, 프로그램의 자동작성 경로에 연결했다는 뜻은 아니다.

## 작성 요청을 받으면

1. 사용자가 준 양식의 대주제·소주제와 각 항목의 작성요령을 원문 기준으로 확인한다. 제목·범위·분량·표 요구를 임의의 공통 목차로 바꾸지 않는다.
2. 자유롭게 적은 연구내용에서 대상, 문제, 목표, 방법, 자료·장비, 기간·기관, 기대 결과를 먼저 정리한다. 정해진 입력 양식을 모두 채우도록 강요하지 않는다.
3. [레퍼런스별 기억 90건](authoring_reference_memory.json)에서 분야뿐 아니라 과제 성격과 해당 소주제에 맞는 사례를 선택한다. 필요하면 소주제별로 서로 다른 사례를 참고한다.
4. 참고 사례의 설명 순서와 구체화 방법을 사용자의 실제 연구내용에 적용한다. 남의 문장·수치·실적·기관·연차를 그대로 복사하지 않는다.
5. 사용자가 짧은 내용을 줘도 핵심 의도를 보존하며 문단·표로 풀어 쓴다. ‘그대로 작성’은 사용자의 연구 의도를 충실하게 반영한다는 뜻이지, 타 과제의 내용을 전용한다는 뜻이 아니다.
6. 연구자가 결정해야 할 중요한 누락사항만 한 번에 모아 확인한다. 근거가 있는 부분부터 작성하며 문장마다 질문하지 않는다. 미확정 수치·예산·인력·협약·실적은 확정 사실로 만들어내지 않는다.
7. 소주제 사이의 목표·세부과제·연차·기관 역할·평가지표가 서로 일치하는지 검토한다. 조사 사실, 사용자가 제공한 사실, 계획·제안을 구분한다.
8. 기준값·정책·표준·동향은 필요할 때 최신 출처로 재확인한다. 과거 보고서의 성과를 이번 과제의 달성 실적으로 바꾸지 않는다.
9. 사진·표·그래프·도식의 구성을 검토할 때 [시각자료 사용 기억](AUTHORING_VISUAL_REFERENCE_MEMORY.md)을 읽고, 사례별 실제 삽입 위치·형식·설명 목적을 참고한다. 캡션 기반 추정과 실제 지면 관찰을 구분한다.

## 레퍼런스 기억에 저장한 항목

- 원문 제목·식별번호·출처
- 과제 분야·성격과 연구내용
- 확인된 설명 전개 방식
- 참고하기 좋은 소주제
- 사용자의 설명에서 찾아야 할 정보 또는 필요한 경우 물어볼 항목
- 자료 확인 범위와 한계

입력 항목은 조사자가 작성 지원을 위해 제안한 것이다. 원문 공식 작성요령으로 표시하지 않는다. 공개 초록에서 확인하지 못한 소주제의 세부 작성 방식을 읽은 것처럼 주장하지 않는다.

## 소주제 적용의 기본 원칙

| 소주제 | 반영할 내용 |
|---|---|
| 필요성 | 실제 대상·환경 → 현재 문제 → 기존 방식의 한계 → 연구 필요 |
| 목표 | 최종 산출물 → 세부목표 → 판단 기준과 조건 |
| 연구내용 | 작업별 입력 → 처리·실험 → 산출물 → 다음 작업과 연결 |
| 연구방법 | 방법 선택 이유 → 비교·통제 조건 → 측정·검증 절차 |
| 연차계획 | 앞 단계 산출물 → 다음 단계의 확장 → 연도별 완료 조건 |
| 추진체계 | 실제 참여주체 → 담당 작업 → 협업·자료 전달 |
| 활용·기대효과 | 결과물 → 사용할 주체·현장 → 필요한 후속 작업 |

이는 고정 목차나 공식 심사 기준이 아니라 작성 보조 원칙이다. 기초연구는 질문·가설·기전 검증, 표준화는 요구·규격·합의, 인프라는 구축·운영·이용 지원 등 과제 성격에 맞게 달리 구성한다.

## 기억 범위

기존 S01~S40과 정보통신 추가 50건을 합친 90건을 연결했다. 정보통신 번호 I32는 제목·초록 불일치로 제외하고 I51로 대체되어 번호에 공백이 있다.

- [기존 40건 분석](../exa-results/msit-research-writing-2026-09-25/사례별_분석.md)
- [정보통신 50건 분석](../exa-results/ict-references-2026-09-25/정보통신_추가레퍼런스_50건.md)
- [소주제별 작성 방식 조사](../exa-results/msit-research-writing-2026-09-25/조사결과.md)
- [정보통신 작성 방식 조사](../exa-results/ict-references-2026-09-25/정보통신_조사요약.md)

이 자료들은 공개 연구보고서 요약문 중심의 분석이다. 실제 제출 계획서 90건을 확보하거나 각 보고서 전문을 모두 읽은 것이 아니다. 별도로 확인한 PDF 3건은 기존 조사 자료에 남아 있으며 이번 90건 연결 목록의 추가 건수로 세지 않았다.

후속 시각자료 조사에서는 위 90건의 원문 PDF를 모두 확보하고 공개 표·그림 목록 4,947개 및 지면의 배치·형식·설명 목적을 별도 저장했다. 2026-09-26 기준 실제 지면 개요 검토는 596쪽(기존 473쪽)이며, 전체 10,333쪽의 텍스트·내부 구성 기계 점검도 수행했다. 이는 전문 정독이나 모든 시각자료의 개별 검증 완료가 아니다. 확인 수준과 미검토 범위는 [시각자료 기억](AUTHORING_VISUAL_REFERENCE_MEMORY.md), [사례별 기록](authoring_visual_reference_memory.json)에 남겼다. 기존 초록 중심 기록을 전문 검증 기록인 것처럼 덮어쓰지 않는다.

실제 작성에서는 [참고자료 삽입 기준](AUTHORING_REFERENCE_INSERTION_STANDARD.md)에 따라 소주제·설명 목적·위치·형식·필요한 실제 자료·출처·미확정 상태를 정한다. 양식 요구를 우선하고, 자료가 부족하면 계획도/평가계획으로 구분하거나 보완 대기로 남긴다. 가짜 성능 그래프와 실물 사진을 만들지 않는다.

## 작업 범위

이번 요청은 기억·작성 기준 저장이다. 프로그램 코드, 자동작성 요청문, 기존 사용자 양식·문서·저장값을 바꾸지 않는다. 이후 프로그램 연결을 요청받으면 별도 구현·시험 작업으로 진행한다. 이 프로젝트는 내부용이며 임의로 외부 공개·제출하지 않는다.
