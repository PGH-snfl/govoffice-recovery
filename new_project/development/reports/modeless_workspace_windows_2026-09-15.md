# 관리 창을 동시에 조작하는 방식으로 변경

## 적용

- 기관, 서식 프리셋, 즐겨찾기 관리, 개인정보 선택 저장, 데이터 표 관리, 새 값 입력 관리, 문서 작성 화면은 Show()로 연다. 다른 창의 입력을 막지 않는다.
- workspace_windows.ps1이 창을 종류별로 관리한다. 같은 창을 다시 요청하면 기존 창을 복원·활성화한다. 창을 닫으면 등록을 해제한다.
- 삭제 확인, 작은 값 편집, 기본정보 편집, 파일 선택, 서식 저장 확인/출력값 확정처럼 결과를 기다려야 하는 대화상자는 여전히 모달 방식이다. 이 확인창까지 모두 비모달로 전환한 것은 아니다.
- 창 생성 함수가 반환된 뒤에도 이벤트가 해당 창의 컨트롤을 사용하도록 클로저를 적용했다. 지역 갱신 함수는 수명이 유지되는 스크립트 블록으로 변경했다.
- 개인정보 및 즐겨찾기 관리 창이 닫히면 호출한 화면의 목록을 갱신한다. 종료 중인 앱에서는 이 갱신을 건너뛴다.
- 작성 창의 상태 확인 타이머는 창 생성 함수 반환 후에도 계속 실행되며, 창이 닫힐 때 정리한다.
- 다른 창에서 저장 정보가 변경되었을 때 예전 스냅샷으로 저장하는 요청을 거부한다. 새 값 관리에도 새로고침 버튼을 추가했다.
- 짧은 개인정보 편집/검토와 필드 드래그 중에는 공통 상태 확인 콜백을 C# 측에서 잠깐 정지하고 반드시 복구한다. 창 이동 중 정지 보호도 유지한다.

## 검증

- 관련 시험 63개 통과: 개인정보 표·관리 버튼, 이전 모달 편집 수명주기, 두 단계 작성, 즐겨찾기, 원본 배치, 상태 확인 보호, 내부 설치 경로.
- workspace_windows_probe.ps1에서 실제 WPF 창 세 개를 동시에 생성했다. 사용자 화면을 가리지 않도록 투명 창과 모의 데이터를 사용했다.
- 메인 및 세 창의 Windows 입력 활성 상태, 생성 함수 반환 후 버튼 콜백, 작성 창 타이머, 중복 열기, 닫기/재개방, 메인 종료 시 소유 창과 등록 정리를 확인했다.
- 기존 사용자 프로그램·한글 문서·프로필·로그인에는 손대지 않았다. 새 창 관리 코드와 C# 보호 코드는 프로그램 재실행 후 로드된다.
