# 등록 양식 삭제: 접근 거부 대응

> 아래 기록의 ‘삭제 기록으로 목록에서 제외’ 구현은 사용자 요청에 따라 철회했다. 현재 상태는 `template_delete_strict_2026-09-15.md`를 참고한다.

사용자 오류는 WinError 5(액세스 거부)로 보고되었으나 전체 경로와 원인은 확정되지 않았다. 실제 등록 폴더를 임의로 삭제하거나 권한을 바꾸지 않았다.

## 재현 및 수정

- 임시 시험 양식의 `template.hwp`를 삭제 공유 없이 열어 두면 등록 폴더 이름 변경이 실제 Windows에서 **WinError 5**로 실패함을 확인했다. 동일 시험 프로세스에서 파일 핸들을 유지하여 재현했다. 이는 가능한 원인을 재현한 것이며 사용자 PC에서 같은 잠금이 원인이었다고 확정한 것은 아니다.
- 정상일 때는 종전대로 등록 폴더를 삭제 보관 폴더로 옮긴다.
- 접근 거부·공유 위반으로 이동이 차단되면 파일을 강제로 옮기지 않는다. 원래 위치에 보존하고 별도 삭제 기록을 원자적으로 저장하여 등록 목록에서 제외한다.
- 삭제 기록은 다시 실행해도 적용된다. 삭제된 양식은 새 작업·양식 조회에서 차단하지만 기존 작업은 자기 사본으로 계속 작성할 수 있다.
- 삭제 기록 저장에도 실패하면 성공으로 응답하지 않는다. 정보 읽기/삭제 기록 저장 등 실패 단계와 대상 경로, 오류 번호를 표시한다.
- 사용자나 관리자 권한을 변경하거나 실행 중인 한글·다른 앱을 종료하지 않는다. 실제 사용자 양식은 삭제하지 않았다.

## 확인

- 삭제 전용 시험 13개: 실제 Windows 파일 잠금, WinError 5 대체 처리, 보관 폴더 생성 거부, 삭제 기록 저장 실패, 재실행 후 삭제 유지, 기존 작업 계속 작성, 경로 검사 등을 확인했다.
- 관련 회귀 시험 총 141개 통과.
- 화면 시험에서 실패 시 목록 유지, 실패 단계 표시, 이동 차단 시 ‘원래 위치에 보관’ 안내와 기존 삭제/취소/마지막 양식 처리도 확인했다.

복구는 이동 보관본 또는 원래 등록 폴더와 삭제 기록을 이용하는 수동 방식이며 앱의 복원 버튼은 아직 없다. 이 변경을 적용하려면 프로그램을 다시 실행해야 한다.
