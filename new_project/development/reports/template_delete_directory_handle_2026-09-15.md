# 하위 폴더가 열린 양식 삭제 수정

## 화면 및 진단

- 제공된 화면은 `templates/cb8a1dd11c704f1297efc205fa6e6f95`에서 `deleted_templates/cb8a1dd11c704f1297efc205fa6e6f95_cc3ac6869cca4feb8d827b4d06bff0d0`로 폴더를 옮길 때의 WinError 5였다. 기존 원문 오류 출력으로, 새 오류 처리 코드 적용 전 실행 상태다.
- 해당 등록 폴더 및 보관 폴더에서 사용자 FullControl 권한을 확인했다. 등록 폴더와 20개 하위 항목의 삭제 접근 검사 모두 성공했고 Windows Restart Manager의 파일 점유 조회에는 프로세스가 나오지 않았다. 권한 변경 또는 사용자 앱 종료는 수행하지 않았다.
- 별도 임시 폴더에서 `guides` 디렉터리를 읽기 접근/전체 공유로 열면 파일 잠금 검사에 실패하지 않더라도 상위 폴더 rename이 실제 WinError 5로 실패했다. 같은 조건에서 검증된 복사 후 원래 폴더 제거는 성공했다. 사용자의 실제 점유 프로세스까지 특정한 것은 아니다.

## 수정

- 먼저 기존 원자적 폴더 이동을 시도한다.
- WinError 5가 지속될 때 정확한 등록/보관 위치와 하위 연결 폴더 유무를 검사한다.
- 개별 파일/폴더가 삭제 접근을 허용하지 않으면 중단한다. 다른 프로그램을 강제 종료하지 않는다.
- 보관본을 복사하고 모든 파일 SHA-256(파일 내용 비교용 해시) 및 폴더 구성을 비교한다. 복사 도중 원본이 변경되었는지도 확인한다.
- 검증 후 등록 폴더를 실제 제거한다. 정리 실패 시 보관본을 보존하고 없어진 파일을 복원하며 실패로 응답한다.
- 성공은 등록 폴더가 제거된 후에만 반환한다. 목록 숨김 기록은 사용하지 않는다.

## 검증

- 삭제 전용 18개 시험 통과: 실제 하위 폴더 열린 상태, 배타적 파일 잠금, 권한 거부, 보관 복사 실패, 검증 불일치, 부분 정리 실패 후 복원, 하위 연결 폴더 차단 포함.
- 관련 회귀 시험 총 146개 및 화면 작업 흐름 시험 통과.
- 실제 사용자 등록 양식은 진단에서 읽기만 했으며 삭제하지 않았다. 검증 중 제거한 것은 자동 생성한 임시 시험 자료뿐이다.
- 실행 중인 이전 백엔드에는 코드가 자동 반영되지 않으므로 프로그램 재시작 필요.
