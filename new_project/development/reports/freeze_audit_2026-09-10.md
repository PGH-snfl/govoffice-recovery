# 개인정보 저장·데이터 관리 멈춤 점검 — 2026-09-10

## 결론과 범위

요청: 한 번 기능을 사용한 뒤 다른 기능이 안 되는 현상을 전체 실행 경로에서 점검. 사용자가 지목한 버튼은 개인정보 저장, 데이터 관리.

실제 사용자 증상의 최초 원인은 아직 확정하지 못했다. 아래 두 공통 장애 경로는 별도 재현에 성공했다. **진단 단계이며 운영 소스 수정/해결 완료로 분류하지 않는다.** 한글 문서와 저장된 사용자 정보는 이 진단에서 변경하지 않았다.

## 재현한 공통 장애 경로

1. **한 번의 시간 초과가 전체 기능을 계속 차단한다.**
   - `launch_gui.ps1`의 `Send-Backend`는 시간 초과 후 백엔드를 성공적으로 정리해도 `BackendUnhealthy=true`로 고정한다.
   - 이후 문서와 관계없는 `user_profile_get`, `user_profile_table_mutate`, 수동 `connect`까지 같은 입구에서 차단된다.
   - 진단은 실제 요청 상태 처리 함수를 추출하고 시간 초과를 주입했다. 세 후속 요청 모두 차단됨을 확인했다. 실제 한글을 멈추거나 사용자 데이터를 수정하지 않았다.
   - 이 조치는 불명확한 한글 작업을 재실행하지 않기 위한 안전장치다. 단순히 플래그만 해제하면 안 된다. 한글 작업의 재시도 금지와 로컬 데이터 접근 제한을 분리해야 한다.

2. **오류 출력 통로를 읽지 않아 백엔드가 막힐 수 있다.**
   - `Start-BackendProcess`는 stderr를 리디렉션하지만 지속적으로 읽는 코드가 없다. stdout만 기다린다.
   - 테스트 전용 Python이 stderr에 256 KiB를 쓴 뒤 READY를 출력하게 하자, 응답 읽기가 500 ms 한도에서 시간 초과되었다. 같은 프로세스의 stderr를 비우자 원래 응답이 즉시 완료되었다.
   - 위 상황은 1번 전체 차단으로 이어질 수 있다. **사용자 실행에서 실제로 256 KiB 오류가 발생했다는 뜻은 아니다.**

재현 스크립트: `tests/freeze_transport_probe.ps1`
결과: `STDERR_BACKPRESSURE_CONFIRMED`, `GLOBAL_TIMEOUT_LOCK_CONFIRMED`.

## 추가 점검 대상 (증상과 인과관계 미확정)

- `Show-Error`가 소유 창 없는 메시지 상자를 연다. 메인 창은 Topmost다. 오류 대화상자가 어느 창을 소유하고 어디에 표시되는지 실제 화면에서 추가 확인해야 한다.
- 통신 응답을 기다리며 중첩 DispatcherFrame을 돌리므로 다른 버튼 이벤트가 들어올 수 있다. 중복 요청은 거부하지만 거부 알림이 다시 모달 창을 열 수 있다.
- 데이터 관리의 Drop 처리 안에서 통신과 전체 표 재구성을 즉시 수행한다. 드래그 종료 이후 반영하도록 분리할 필요가 있는지 재현 검사가 필요하다.
- 표 생성이 여러 번 전체 필드 목록을 검색한다. 대량 데이터 성능 가능성은 있으나 현재 사용자 데이터 크기로 인한 정지라고 판단할 근거는 없다.

## 통과한 검사와 한계

- 전체 기존 자동검사: **324개 실행, 실패 0, 2개 건너뜀**. 실제 한글 기능 324개를 클릭 검증했다는 의미가 아니다.
- `tests/window_lifecycle_probe.ps1`: 운영 창 초기화 및 개인정보 저장/데이터 관리의 실제 WPF ShowDialog/닫기 흐름을 3회 교대로 실행. Dispatcher가 계속 작동함을 확인. 저장 응답/선택 데이터는 테스트 대역이므로 실제 한글 선택·영구저장 검증이 아니다.
- 기존 검토 창 테스트, 대기 처리 테스트, 타이머 중지/복구 테스트도 통과했다.
- GUI는 실행되어 화면에 표시되었지만, 이 세션의 화면 제어 도구가 해당 PowerShell 기반 WPF 창을 조작 대상으로 제공하지 않아 사용자와 같은 직접 클릭 재현은 완료하지 못했다. 외부 문서에 자동화 명령을 보내거나 새로운 한글 문서를 만들지 않았다.
- 기존 로그에는 검토 창의 생성·종료 흔적이 있으나, 이번에 확인한 시간 초과 경로가 사용자 증상 직전에 발생했음을 입증할 기록은 없다.

## 수정 우선순위

1. 백엔드 stderr를 UI 스크립트 콜백 없이 비동기로 비우고 크기 제한을 둔다. 개인정보가 포함될 수 있으므로 원문 무제한 로그를 남기지 않는다.
2. 실패한 한글 명령은 재전송하지 않는다. 한글 상태 확인이 필요한 동안에도 로컬 프로필 조회·수정은 가능하도록 장애 영역을 분리한다.
3. 대기 중 버튼 상태, 모달 오류 창 소유 관계, 드래그 종료 후 반영을 정리한다.
4. 요청 시작/종료/시간 초과/후속 거부 사유를 값 없이 기록하고, 두 버튼의 실제 연속 사용을 다시 검증한다.

운영 파일을 임의로 대폭 변경하지 않고 진단용 스크립트와 이 보고서만 추가했다. 수정 후에는 기존 검사를 유지하면서 동일 시간 초과 및 오류 출력 시험에서 로컬 기능이 살아있는지 검증해야 한다.
