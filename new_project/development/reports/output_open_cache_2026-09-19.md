# 최종 출력본 열기: 누락된 전용 프로세스 캐시 초기화 수정

## 원인

사용자 화면의 오류는 작성 실패가 아니라 완료 후 `최종 출력본 한글 파일 열기` 동작의 실패였다. 호출 경로는 `authoring_open_output` → `open_output_hwp` → 별도 Python 프로세스 `hwp_output_open.py` → 관리 문서 열기다. 메인 프로세스나 변환/추출 프로세스에 설정한 `win32com` 캐시 경로는 이 새로운 프로세스에 전달되지 않는다. 출력본 열기 실행부만 초기화가 누락되어 공유 임시 코드에서 `CLSIDToClassMap`을 찾다가 실패했다.

## 수정

- 출력본 열기 프로세스도 한글 어댑터를 불러오기 전에 독립 임시 생성 코드 경로를 설정한다.
- 공유 임시 폴더를 삭제하거나 기존 한글 문서에 재접속하지 않는다.
- 변환/추출/출력본 열기 실행부 모두 독립 초기화하는지 자동 검사 추가.

## 실제 검증

- 버튼이 호출하는 `AuthoringCommands.handle(authoring_open_output)`을 그대로 실행했다.
- 작업 `f005b3f9862045cc89377dce9a0ac9d3`의 `수소 핵융합 기술` 결과 문서에서 작업 완료, 실제 문서 열림, 창 표시, 편집 가능, 경로 일치를 확인했다.
- 대상: `연구계획서_검토초안_fd2ab44a.hwp`.
- 열기 전후 SHA-256 파일 내용 동일. 문서 재작성/저장/사용자 기존 창 종료 없이 출력본 창을 남겼다.
- 출력본 열기/캐시/메인 프로토콜/문서 소유권 관련 시험 47개 통과.
- 실행 파일을 매번 새로 읽는 경로이므로 이미 켜진 프로그램의 다음 열기 요청에도 수정된 자식 프로세스가 사용된다.
