# 최종 출력본 열기 수정

- 기존 화면은 `.hwp` 경로를 `Start-Process`로 실행하고 성공 여부를 확인하지 않았다.
- 실기 진단에서 Hwp.exe 응용 프로그램 오류 `0xe0434352`를 관찰했다. 실행 요청이 정상 반환/종료 코드 0이어도 대상 문서 창은 나타나지 않았다. 네이티브 오류의 내부 원인은 확정하지 않았다.
- 같은 출력본은 기존 복구 어댑터의 전용 문서 열기로 경로 일치, 문서 열림, 창 표시, 편집 가능을 확인했다. 도우미 종료 뒤에도 창이 유지됨을 확인했다.
- 새 `authoring_open_output` 요청은 저장된 완료 작업의 경로를 읽고, 작업 폴더 내부 출력본만 허용한다. 화면에서 임의 경로를 전달하지 않는다.
- `hwp_output_open.py`가 별도 프로세스에서 전용 연결로 열고 실제 경로/표시 상태를 검증한다. GUI 스레드에서 COM 응답을 기다리지 않는다. 45초 제한을 두며 다른 사용자 한글 문서를 닫지 않는다.
- 화면은 열기 작업을 비동기로 조회하고 중복 클릭을 막는다. 오류는 다음 상태 조회에도 유지하며 수동 재시도가 가능하다. 자동 열기는 새로 시작/재개한 작업당 한 번 유지한다.

## 검증

- Python: 출력 열기, 기존 작성 흐름, AI 작성요령 추출 관련 27개 테스트 통과.
- PowerShell: 실제 화면 콜백을 사용하는 workflow probe, UI 구조 probe 통과. 실제 범정부오피스 창은 화면 도구에 노출되지 않아 실행 중인 그 창의 버튼 클릭은 검증하지 못했다.
- 실기: `b028ca330b724e51a334ffe98adc6701` 출력본을 전용 어댑터로 열어 정확한 경로와 visible=true 확인.
- 수정된 `open_output_hwp` 함수로 `첨부자료/출력열기_진단_20260915/최종출력본.hwp` 사본을 열어 실제 한글 창과 editable=true 확인.
- 원본/기존 출력 파일 내용은 변경하지 않았다. 진단 사본은 위 폴더에 남겨 두었다.

변경된 화면 및 백엔드는 프로그램의 다음 실행부터 로드된다.
