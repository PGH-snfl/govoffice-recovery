# 개인 탭 재진입 시 창 입력 잠김 — 원인 확인

## 결론

운영 `launch_gui.ps1`은 메인 Window를 만든 다음 WPF Application을 생성한다. 이 순서에서는 메인 창이 Application.Windows 관리 목록에 등록되지 않는다. 보조 창을 닫고 다음 보조 창을 여는 상황에서 메인 창이 비활성화된 채 보조 창이 표시되지 않는 현상을 격리 시험으로 재현했다. Application을 먼저 생성하면 같은 시험에서 정상 작동했다.

사용자 실행과 일치하는 직접 증상은 **계산 스레드 정지가 아니라 메인 창의 입력 비활성화**다. 이 조사에서는 운영 기능 코드 수정 및 추가 재시작을 하지 않았다.

## 실제 실행 증거

- 대상 진단 프로세스: 23796. 진단 로그 `runtime/freeze_diagnostic_20260915_120129_23796.log` (UTC 기록).
- 한국 시각 12:03:11: 데이터 표 관리 첫 실행. 보조 창 표시 정상.
- 12:03:13~18: 더블클릭 수정 창 3회 열기 및 닫기 완료.
- 12:03:20: 데이터 관리 창 닫기 완료.
- 12:03:22: 연결되지 않은 한글의 선택 영역 분석 시도. 오류 안내는 12:03:23에 종료됨. 열린 오류창에 갇힌 상황이 아님.
- 12:03:24: 데이터 표 관리 두 번째 실행. 데이터 조회 및 표 생성은 완료되나 창 Loaded 기록 없이 표시 함수가 반환됨. 그 후 사용자 클릭 기록이 사라짐.
- 그 뒤에도 1.5초 문서 상태 조회의 시작과 종료가 정상 반복되고 화면 스레드 응답 확인도 계속 갱신됨. 요청 시간 초과/백엔드 전역 차단 증거 없음.
- `runtime/frozen_windows_snapshot.json`: 메인 창 1902934는 Visible=true, Enabled=false, Hung=false. 같은 프로세스의 다른 창은 모두 Visible=false. 실제 표시된 오류창이나 편집창 없음.

## 격리 재현

스크립트: `development/diagnostics/modal_lifetime_probe.ps1`

한글 연결 및 사용자 데이터 접근 없이, 별도 Windows PowerShell 프로세스의 투명 시험 창만 사용했다. 두 보조 창 사이에 500ms 간격을 두어 종료 후 예약 처리가 실행되도록 했다. 각 프로세스에 외부 7초 제한을 적용했다. Loaded 이벤트를 기준으로 시험 창을 닫았으며, 실제 사용자 창은 조작하지 않았다.

| 검사 | 현재 생성 순서 | Application 먼저 생성 |
|---|---|---|
| 메인 창 관리 목록 등록 | False | True |
| 첫 보조 창 표시 | Loaded 발생 | Loaded 발생 |
| 첫 보조 창 닫은 뒤 메인 입력 | True | True |
| 두 번째 보조 창 표시 | Loaded 없음 | Loaded 발생 |
| 두 번째 시도 후 메인 입력 | **False** | **True** |

두 조건 모두 시험 프로세스 자체는 정상 종료했다. 최초 시험에서는 투명 창의 ContentRendered를 기다려 시험이 진행되지 않았으므로 그 시간 초과 결과는 증상 재현 근거에서 제외했다.

## 수정 방향 및 범위

Application을 메인 Window보다 먼저 초기화하고 메인 창을 명시적으로 지정하는 것이 우선이다. 개인 정보, 한글 연결, 대표필드 이동 알고리즘을 변경할 필요는 없다. 기존 창 수명 검사는 첫 ContentRendered 안에서 연속 실행해 창 종료 뒤 예약 처리 시점을 놓칠 수 있으므로, 분리된 이벤트 시점의 두 번째 열기 검사로 보완해야 한다.

과거에 별도로 재현한 stderr 정체 및 시간 초과 후 전역 차단 문제는 독립 결함이며 이번 증상의 원인으로 혼동하지 않는다.

위 내용은 수정 전 진단 결과다. 이후 적용 내역은 다음과 같다.

## 사용자 요청에 따른 수정 및 검증

- `launch_gui.ps1`: 메인 창을 읽어 생성하기 전에 Application을 초기화하도록 순서를 수정했다.
- 메인 창을 Application.MainWindow에 명시적으로 연결하고 종료 조건을 OnMainWindowClose로 지정했다. 보조 창을 닫는 것은 프로그램 종료 조건이 아니다.
- `development/tests/profile_reopen_lifecycle_probe.ps1`: 실제 운영 초기화 구간과 개인 탭 창 함수를 이용한 회귀 검사를 추가했다. 데이터 창/분석 창 12회와 실제 중첩 텍스트 수정창 6회를 서로 다른 이벤트 처리 시점에 열고 닫는다. 매번 창 표시, 메인 창 등록 및 입력 가능 상태를 확인한다. 한글은 연결하지 않고 개인정보 응답과 저장은 시험용 대역만 사용한다.
- 수정 전 새 검사는 `Main window missing from application ownership`으로 실패했다. 수정 후 동일 검사가 통과했다.
- 관련 검사 21개 통과: `test_profile_table_ui`, `test_profile_table`, `test_window_poll_guard`, `test_launcher`.
- 수정된 전체 런처를 진단 미리보기로 실행하여 표시와 자동 종료가 정상임을 확인했다.
- 사용자에게 재실행을 알리고 이전에 실행했던 진단 프로세스 23796 및 그 보조 프로세스 10128을 검증 후 종료했다. 한글 프로세스는 종료하지 않았다. 수정된 진단 실행 프로세스는 2724다.

실제 사용자 문서로 모든 기능을 검증한 것은 아니다. 진단 기록은 유지하여 사용자 재확인 중 다른 증상이 있으면 구분할 수 있도록 했다.
