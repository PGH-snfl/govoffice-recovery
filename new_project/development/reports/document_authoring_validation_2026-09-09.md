# 소주제 자동작성 구현·검증 — 2026-09-09

## 결과

기존 예시 생성 경로를 유지하고 서울과학기술대학교에 ‘과제 문서 순차 작성’을 추가했다.
양식 등록 → 주제별 작성요령 저장 → 과제 정보 입력 → 외부 Codex 요청 → 응답 검사 → 문서 반영 → 한글 저장 경로를 구현했다.

## 시험 범위 및 결과

- 단위·회귀 시험 **86개 통과**: 문서 자동작성 18개, Codex 통신·설치 탐지 6개, 기존 기후부 예시·백엔드·사용자 경로·원본 화면·기관 목록 시험 포함.
- 새 작성 화면: PowerShell 구문 분석, 실제 WPF(Windows Presentation Foundation·윈도우 화면 구성 기술) 객체 생성,
  21개 구성요소 연결, 한글 문자열, 동의 항목 기본 해제 확인. 사용자가 보는 창에서 실제 마우스로 전체 버튼을 누르는 시험은 하지 않았다.
- 기후부 양식 33개 소주제, 666개 입력 위치, 원문 비어 있지 않은 문단 3,074개 보존 대조.
- 동일 이름 소주제의 식별번호·문단 위치 중복 방지 확인.
- 순차 응답 전달, 실패·중단·재시작, 완료 항목 중복 입력 방지, 잘못된 응답 차단, 원본 무결성 확인.
- 정상 사용자 환경에서 기존 ChatGPT 방식 Codex 로그인 상태 확인. 로그인 토큰·비밀번호는 출력하지 않았다.
- 가상 과제의 **1-1 소주제 1개(6개 문단)는 실제 Codex가 작성**했다. 나머지 입력 항목은 모의 시험 표식이다.
  실제 과제 전체를 AI가 작성한 것으로 해석하면 안 된다.
- 한글 통합 시험: 새 시험 파일 **62쪽 / 229,376바이트** 저장. **666개 입력값과 각각의 문단 위치**를 한글에서 다시 확인했다.
- 원본 쪽 설정 보존, 원본 파일 해시 불변 확인. 페이지 수가 같다는 뜻은 아니며, 그림·표 넘침까지 시각 검수한 결과는 아니다.

## 시험 중 발견·처리

1. 제한된 실행 환경에서는 Codex가 사용자 홈 폴더를 찾지 못하고 종료했다. 정상 사용자 환경의 인증 상태 조회는 성공했다.
2. 공식 문서 예시의 `readOnly.access`는 설치 버전에서 거절되었다. 설치된 Codex가 내보낸 규격에 맞춰 읽기 전용·네트워크 차단 설정으로 수정하고 실제 응답을 확인했다.
3. 기존 예시 생성기는 고정 예산·기간·기관 조건을 전제로 문서를 삭제/변경하므로 새 작성 경로에서 재사용하지 않았다.
4. 작성요령 원본의 5-1 안내는 다음 5-2 제목 아래에 놓여 있었다. 5-1로 연결하고 5-2의 요령으로 중복 전달하지 않게 했다.
5. 소주제 9개는 입력 위치가 아직 연결되지 않았다. 처리 완료 개수와 실제 작성 개수, 수동 확인 개수를 구분했다.
