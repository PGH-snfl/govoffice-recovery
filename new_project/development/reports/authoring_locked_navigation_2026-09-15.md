# 작업 중·완료 후 단계 이동과 입력 잠금

## 적용

- 상단 4개 단계 버튼과 하단 이전·다음을 항상 표시한다. 입력은 기존 2개만 받는다.
- 작업 시작 전에는 진행 단계, 완료 전에는 완료 단계를 비활성화한다. 처음 단계의 이전, 마지막 단계의 다음은 비활성화한다.
- 작업 중, 중단·실패, 완료 후에도 양식과 작성 내용 단계로 돌아갈 수 있다. 조회 중에는 상태 갱신이나 완료 알림이 화면을 강제로 이동시키지 않는다.
- 시작 후 양식 변경·등록을 차단하고, 주제와 세부 내용은 회색 읽기 전용으로 표시한다. 텍스트 선택·복사는 가능하다.
- 개인정보 표는 회색으로 표시하고 더블클릭 수정과 내부 수정 콜백을 모두 차단한다. 접기·펼치기, 열 너비 조절은 유지한다.
- ‘입력 내용 확인’은 작업을 지우거나 입력 잠금을 풀지 않는다. 재개는 기존 입력값을 그대로 사용한다.
- 작업에 확인용 그룹과 값의 사본을 저장한다. 화면의 임의 값이 아닌 서버가 검증한 입력값만 사용하며, 재열기 시 현재 프로필 대신 작업 사본을 표시한다. 기존 작업은 저장된 문서 위치와 값으로 확인 표를 구성한다.
- 진행·완료 영역에 스크롤을 적용해 작은 창에서도 결과 버튼에 접근할 수 있게 했다.

## 검증

연결·자료조사·문서 작성·작성 흐름·자동 검사·개인 정보 표 관련 자동 시험 87개가 통과했다.

실제 화면 코드의 클릭·더블클릭·단계 이동·상태 갱신을 모의 백엔드로 시험했다. 실제 통신과 같은 JSON → PowerShell 객체 변환도 적용했다. 작업 중 이전 이동, 완료 순간 조회 위치 유지, 완료 후 앞뒤 이동, 입력값 편집 차단, 표 접기·펼치기, 재개 시 잠금 유지, 저장된 다른 작업 불러오기를 검사했다.

작업 사본 시험에서는 중복 문서 위치를 한 항목에 보존하고, 현재 프로필을 변경해도 과거 값을 표시하며, 서로 다른 값이나 잘못된 위치를 합치지 못하는 것을 확인했다.

`authoring_locked_navigation_preview/`에서 회색 입력 영역과 상단·하단 이동 버튼, 작은 창 완료 화면을 렌더링하여 확인했다. 사용자가 실행 중인 프로그램이나 한글 문서는 닫거나 재시작하지 않았다. 실제 AI 재호출 없이 화면·저장 상태 회귀 검증을 진행했다.

프로그램 재시작 후 적용된다. 진행 중인 작업이 있다면 강제 재시작하지 말고 완료 또는 중단 후 재시작한다.
