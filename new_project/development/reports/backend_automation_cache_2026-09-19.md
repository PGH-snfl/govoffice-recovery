# 메인 프로그램 한글 Automation 생성 실패 수정

## 확인

- 공유 `gen_py/3.13`의 한글 타입 라이브러리 모듈 `7D2B6F3C-1D95-4E0C-BF5A-5EE564186FBCx0x1x0`를 읽었을 때 `__file__=None`, `CLSIDToClassMap=False`, `CLSIDToPackageMap=False`였다. 불완전한 네임스페이스 모듈이 생성된 코드처럼 선택되는 상태다.
- 문서 변환/추출용 프로세스는 이미 독립 캐시를 사용했으나 `gui_backend.py` 메인 프로세스는 공유 캐시를 사용하고 있었다.
- 이번 사용자 보고에는 전체 세부 오류가 없었으므로 모든 Automation 실패 원인이 이 하나라고 단정하지 않는다. 확인된 메인 연결 결함을 수정하고 실제 연결 경로로 검증했다.

## 변경

- 메인 백엔드 시작 시 한글 라이브러리보다 먼저 전용 임시 `gen_py` 경로를 설정한다.
- 실행 중인 COM 클래스/프록시를 바꾸거나 공유 캐시를 삭제하지 않는다.
- 백엔드 종료 정리 후 자기 전용 임시 캐시만 정리한다.
- 이후 Automation 오류의 동작명/원문 오류/실행 환경을 `config/diagnostics/last_hwp_connection_error.json`에 기록한다. 기록 실패는 원래 오류를 가리지 않는다.

## 검증

- 실제 `gui_backend.py`를 별도 시험 데이터 경로로 실행하고, 기존 검증 HWP의 임시 사본을 프로그램 소유 문서로 열었다.
- READY → 문서 열기 → 상태 확인(managed) → 저장 없이 정상 종료 → 백엔드 종료 모두 성공했다.
- 원본 및 시험 사본의 파일 내용 해시가 동일했다. 사용자가 열어 둔 문서나 기존 한글 프로세스를 임의로 종료하지 않았다.
- 연결/백엔드/어댑터 관련 자동 시험 90개 통과.
- 실행 중인 이전 백엔드에는 자동 반영되지 않으므로 범정부오피스 재실행이 필요하다.
