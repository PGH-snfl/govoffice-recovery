# 창 이동 중 자동 조회 차단 — 2026-09-10

## 확인된 경로

지난 개인정보 검토 창 수정에서는 해당 창을 여는 동안 메인 문서 상태 조회와 선택 감지 타이머를 중지했다.
새 `Open-DocumentAuthoring`은 이 격리를 거치지 않고 자체 `ShowDialog()`를 실행했으며,
1초 간격 진행 조회와 메인 창의 자동 조회가 함께 실행될 수 있었다.
기관·메인 창의 `DragMove()` 및 Windows 기본 제목 표시줄 이동 중 자동 조회를 막는 공통 처리도 없었다.

따라서 이전과 같은 종류의 자동 조회 진입 경로가 남아 있는 것은 확인했다.
운영체제 전체 멈춤의 직접 원인까지 확정한 것은 아니다.

## 수정

- 자동작성 화면도 기존 검토 세션 격리를 사용한다. 메인 자동 조회는 창이 닫힐 때까지 쉬고, 이전에 켜져 있던 타이머만 복구한다.
- `gui_poll_guard.cs`는 프로그램의 창이 로드될 때 이동/크기 변경 시작·종료를 감지한다.
- 이동 중에는 PowerShell 이벤트 함수를 호출하기 **전**에 자동 조회를 건너뛴다. Windows 메시지 처리 안에서는 문서 요청·대기·화면 갱신을 하지 않는다.
- 적용 경로: 메인 문서 상태, 한글 선택 감지, 프리셋 선택 상태, 직접 필드 선택 상태, 자동작성 진행 조회의 5곳.
- 제목 표시줄과 기존 사용자 정의 드래그 영역에 공통 적용된다. 이동 동작 자체를 가로채거나 막지는 않는다.
- 창이 이동 중 닫히더라도 잠금 상태가 남지 않으며, 다른 창이 계속 이동 중이면 차단을 유지한다.
- 문서 작성 작업·입력 데이터·서식 추출 로직은 변경하지 않는다. 자동작성 작업은 화면 조회와 별개로 계속 진행된다.
- 내부 실행 구성에 새 공통 파일을 포함했다.

## 검증 범위

프로그램의 실제 메시지 처리 함수에 이동/종료 상태를 메모리상으로 전달해 테스트했다.
운영체제에 메시지를 보내거나 마우스를 움직이지 않았으며, 사용자 한글 파일도 열지 않았다.

- 모의 이동 중 100개 조회 콜백 진입 차단.
- 이동 종료 후 조회 복구, 중복 시작, 여러 창 이동, 이동 중 창 종료, 알 수 없는 종료 메시지 처리 확인.
- 5곳 모두 공통 보호를 거치는지 코드 구조 검사.
- 자동작성 세션 중 메인 조회 중단, 대기열 콜백 차단, 정상·예외·프로그램 종료 때 복구 정책 검사.
- 기존 응답 대기 중 화면 이벤트 처리와 요청 중복 차단 검사.
- 관련 회귀 시험 79개 통과. 자동작성 화면의 21개 구성요소 생성 검사도 통과했다.

실제 데스크톱 전체가 멈추는 현상은 위험을 고려해 재현하지 않았다. 이 검증으로 시스템 전체 멈춤 해소가 입증됐다고 주장하지 않는다.
실행 중인 프로세스는 바꾸지 않았으므로, 수정본은 프로그램 재시작 후 적용된다.
