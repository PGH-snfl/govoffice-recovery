# 대주제별 작성요령 파일과 소주제별 문서 자동작성

2026-09-10 보완. 내부용 범정부오피스의 서울과학기술대학교 기관 기능이다.

## 최신 변경: 주제·작성요령만 AI로 분석

분석 결과는 `guide_outline`에 **대주제 → 소주제 → 작성요령 원문**으로 저장한다. 문서 전체 공통 요령은 별도 구역이며, 입력 필드·역할 분류·불필요한 설명은 이 연결표에 넣지 않는다. 양식 선택 화면의 **주제별 작성요령 보기**에서 읽기 전용 트리로 펼쳐볼 수 있다. 기존 등록본은 자동 변경하지 않으며, 새 등록본부터 이 연결표를 만든다.

글 작성과 자료 조사에는 같은 연결표에서 현재 소주제 요령을 가져온다. 대주제 전체에 적용되는 조건은 그 대주제 아래 소주제에만 적용하고, 다른 소주제의 전용 요령은 섞지 않는다. 전체 공통 요령은 별도로 한 번 전달한다. 동일한 제목도 원문 위치 번호로 구분한다. 입력 위치·저장 정보·앞서 작성한 내용 등 기존 작성 기능은 별도로 유지한다.

2026-09-15 변경. 새 양식 등록은 프로그램이 제목 후보, 작성요령 표, 표 밖 파란 주석을 먼저 추출한다. AI에는 이 원문과 위치 번호만 전달하며 일반 본문·입력 칸·사용자 저장값은 분석 요청에 넣지 않는다. 제목 후보나 작성요령 자체에 개인정보가 있으면 포함될 수 있다.

- AI는 대주제·소주제 제목을 확인하고 작성요령의 적용 주제를 연결한다. 한 표에 여러 소주제의 요령이 있으면 문단 번호별로 각각 연결한다. 요약문으로 원문을 대체하지 않는다.
- 입력 위치는 프로그램이 찾는다. 개인 정보는 기본 항목과 개인 탭의 필드명·별칭을 로컬에서 대조한다. 본문은 확인된 주제 아래의 입력 표시와 설명형 표 항목을 사용한다. 같은 셀의 반복 빈 문단, 기존 내용 앞의 빈 줄, 복합 요소는 덮어쓰지 않는다.
- 용도가 불명확한 빈칸은 빈칸으로 보존하고 개수·위치를 기록한다. 불명확한 제목·작성요령·명시적 입력 표시는 확인 대상으로 남긴다. 자동 재요청은 하지 않는다.
- 제목 확인 1회와 작성요령 연결 최대 3회로 제한한다. 요청량 제한 또는 AI 단계의 240초 대기 예산을 넘긴 부분은 원문과 함께 보존하고 `일부 분석/확인 필요`로 표시한다. 한글 파일 읽기·계정 확인·저장까지 포함한 전체 5분 완료를 보장하는 제한은 아니다.
- 새 등록본은 `analysis_mode=topics_and_guides_only`를 기록한다. `analysis.json`에는 전체 원문, 로컬 입력 판단, 제목/요령 후보, AI의 위치 연결, 미처리 항목을 저장한다. 기존 양식과 진행 중 작업은 변경하지 않는다.

검증: 작은 가상 양식의 실제 AI 왕복 2회 및 분석 저장은 14.13초였다(한글 원본 파일 읽기·출력 시험 제외). 기존 기후부 양식의 로컬 모의 비교는 요청 105회 → 2회, 작성요령 표 23개와 요령/파란 주석 원문 526개 항목의 전체 내용 보존을 확인했다. 큰 원본 양식의 실제 AI 시간이나 모든 입력 위치의 의미 판별 정확도를 실측한 결과는 아니다.

## 이전 방식: 문단 전체 AI 분석 등록

아래는 이전 구현 기록이다. 새 양식 등록은 위의 주제·작성요령 전용 경로를 사용하며 문단 전체 분석은 비교 시험용으로 남겨두었다.

`+ 새로운 양식 등록`은 연결된 AI로 문단·표·색상·주석과 원문 위치를 분석한다. 문서 내용이 외부 AI에 전달된다는 안내를 표시하고, 로그인 연결 후에 등록할 수 있다. 원본 대신 사본을 사용하며 분석 중단 버튼을 제공한다.

새 양식은 별도 작성요령 MD 파일을 생성하지 않는다. 원본 사본, `analysis.json`(원문·분석 판단), `manifest.json`(작성 위치·역할·원문 요령·공통 조건)을 함께 저장한다. 큰 주제·소주제와 원문 위치를 보존하고, 이후 조사·작성 요청에는 저장된 원문 요령과 항목별 조건을 자동으로 전달한다.

입력 역할은 AI 본문, 개인 저장정보, 원본 유지, 빈칸 유지로 구분한다. 제목과 작성요령도 별도로 분류한다. 저장정보 칸은 AI 본문 요청에서 제외하며 연결된 개인값이 없으면 빈칸으로 남기고 검토사항에 기록한다. 개인 탭의 원본 데이터는 바꾸지 않는다.

문단 누락·중복·잘못된 위치·복합 요소 덮어쓰기와 응답 형식을 검사한다. AI 분석 대상은 최대 70문단·압축 표현 기준 약 35,000자 단위로 묶는다(단일 긴 문단과 참고 문맥은 별도). 원문 텍스트는 한 번만 보내고 색상은 문자 위치 범위로 표현한다. 분석 대상과 참고 문맥의 같은 문단을 중복 전송하지 않으며 앞뒤 8문단과 앞서 확인된 제목을 참고한다. 긴 작성요령을 임의로 자르지 않는다.

글이 없는 표·그림 등의 복합 요소 틀은 프로그램이 원본 유지로 확정한다. 표 안의 실제 문단, 파란 주석, 제목, 입력 가능한 빈칸은 AI 분석 대상에 남긴다. 원문 전체와 문단 번호는 저장 파일에 그대로 보관한다. 불확실하거나 형식 검사에 실패한 **항목만 한 번 재요청**하고, 정상 항목은 유지한다. 재요청도 실패하면 해당 항목만 확인 대상으로 남기며 기존의 원문·조건은 버리지 않는다. 진행 화면에는 분석 대상 수와 재검토 항목 수를 표시한다.

연결 오류는 분석 완료로 처리하지 않는다. 모호한 부분만 등록 화면에서 처리 방식을 선택할 수 있고, 선택하지 않으면 원본을 유지한다. 원문 위치 검사로 AI 의미 해석의 정확성까지 보장하지는 않는다. 2026-09-15의 모의 비교에서 기존 기후부 양식 7,419문단의 전송 데이터 문자 수는 약 72% 감소했지만, 실제 AI 분석 시간의 감소율을 측정한 수치는 아니다. 분류할 문단이 많으면 여전히 여러 번 요청해야 한다.

기존 등록 양식과 아래의 기후부 기본 양식 추가 버튼은 기존의 확인된 MD 기반 경로를 유지한다. 이 변경이 과거 양식을 자동 재분석하거나 덮어쓰지는 않는다. 조사 결과 보고서와 작업 프롬프트 MD는 여전히 작업 기록으로 남으며, 없앤 것은 새 양식의 별도 작성요령 MD이다.

## 기존 기후부 기본 양식: v6 파일만 대주제별로 분리

새 등록본 **순차작성 v6 (대주제 파일·소주제별 요령)**에서는 `1.`부터 `8.`까지 큰 주제별로 MD(마크다운, 텍스트 문서 형식) 파일만 묶는다. 파일 안에는 `1-1`, `1-2` 등 소주제 각각의 작성요령 표 내용과 파란 주석·조건을 전부 넣는다. 소주제는 요약하거나 합치지 않는다.
표지·과제 기본정보, 요약문, 본문 과제정보, 별첨은 별도 항목이다. 총 12개 작성요령 파일과 공통 파일 1개를 저장하되, 기존 33개 개별 작성 단위는 유지한다.
‘작성요령’ 표 내용과 해당 항목의 파란 주석·조건을 같은 파일에 보존한다.
파일 안에 `작성요령 표`와 `파란 주석·조건` 구역을 두고 원문 문단 번호를 남긴다. 문장을 요약하거나 재해석하지 않는다.
색이 섞인 문단에서는 파란 글자 부분만 읽는다. 일반 본문과 입력 위치 설명은 작성요령 파일에 섞지 않는다.
표 안에 원래 포함된 예시·참고 내용은 표 내용이므로 보존한다.
1-1/1-2/1-3, 3-1/3-2, 4-1/4-2처럼 한 표에 섞인 항목은 이 양식의 확인된 문단 범위로 분리한다.
5-1 실적 요령도 5-2가 아닌 5-1에 연결한다.

- 23개 작성요령 표의 문단 340개와 표 밖 파란 주석·조건 155개를 보존한다. 선택된 원문 중 미분류 문단은 0개다.
- 기존 33개 항목은 각각 파일 내부에 제목과 전체 요령을 갖는다. AI 요청도 소주제별로 순차 진행한다. 공유 파일에서 현재 소주제 구역만 읽고 공통 요령을 함께 전달한다. 동일 제목이 있어도 고유 구분 표시로 찾으며, 구분 표시가 손상되면 전체 파일을 보내지 않고 오류를 알린다.
- `guides/common.md`에는 공통 표 규칙과 파란 주석의 제출 전 삭제 조건·본문/표 글꼴 규격을 둔다. 모든 소주제 요청에 함께 전달한다.
- 파란 글자 중 빈 입력 표시·기호·표 항목명·입력 예시와 목차의 중복 조건 40개는 제외하고, 원문과 제외 사유를 분류 기록에 남긴다. 사진 삽입 지시와 AI 활용 유형별 작성방향은 유지한다.
- `입력위치.json`과 `manifest.json`에 문서 입력 정보를 별도로 보관한다.
- `작성요령_분류.json`에는 원문 문단별 연결을 기록한다. `전체원문.md`는 새 등록본에서 만들지 않는다.
- 글 작성 요청에도 새 작성요령 파일을 사용한다. 입력 칸을 설명하는 위치·항목 문맥 정보는 별도 자료로 전달한다.
- 기존 등록본과 진행/완료 작업의 사본은 보존한다. 수정된 방식은 v6로 새 작업을 시작한다.
- 다른 임의 양식은 표와 파란 글자를 위치 기반으로 후보 연결하므로 의미별 분류를 완벽히 보장하지 않는다. 일반 양식의 파란 본문/예시 여부와 공통 조건 여부는 등록 검토가 필요하다. 제공된 기후부 양식은 원본 해시(파일 내용 확인값)가 일치할 때만 전용 분류를 적용한다.

48쪽 예제의 실제 AI 연결 검증은 이전 v2 기준 기록이다. v6는 모의 에이전트의 소주제별 호출, 33개 항목별 요령 전체 보존, 입력 위치 1,698개 및 생성 문서 일치를 자동 시험했다. 새로 실제 AI 문서를 작성한 결과는 아니다.
기존 ‘기후부 연구계획서 자동작성 (예시)’와 별도 경로이며 예시 과제·예산을 가져오지 않는다.

## 사용 방법

등록된 양식 삭제: 양식 선택 화면에서 대상을 고른 뒤 **선택한 양식 삭제**를 누르고 확인한다. 목록에서 제거하고 등록 사본을 앱 데이터의 `deleted_templates/<양식번호>_<보관번호>/`로 옮긴다. 원래 선택했던 한글 파일, 개인 저장정보, 기존 작업 사본과 출력 문서는 삭제하지 않는다. 보관 폴더를 통해 수동 복구할 수 있으며 앱 내 복원 버튼은 아직 없다. 양식 처리·문서 작성 중에는 삭제를 막는다.

Windows가 폴더 이동을 거부하는 경우(WinError 5·32·33)는 같은 이동을 최대 4회 시도한다(총 대기 0.9초). WinError 5가 계속되면 각 파일/폴더의 삭제 접근 가능 여부를 먼저 확인한다. 접근 가능한 하위 폴더가 열려 있어 전체 폴더 이름 변경만 거부되는 경우에는 보관본 복사 → 전체 파일 내용과 폴더 구성 검증 → 등록 폴더 제거로 처리한다. 보관본 검증 전에는 등록 파일을 제거하지 않는다. 정리 도중 실패하면 보관본을 보존하고 없어진 등록 파일을 복원하며 성공 처리하지 않는다. 배타적으로 사용 중인 파일이나 권한 거부가 있으면 삭제를 중단한다. 목록에서만 숨기거나 권한을 강제로 바꾸지 않는다.

2026-09-15 화면 변경: 필수 입력은 작성 주제·주제 세부 내용 두 가지다. 상단에는 **01 양식 선택**, **02 작성 내용**, **03 작업 진행**, **04 완료** 이동 버튼, 하단에는 **이전·다음**을 표시한다. 작업 중과 완료 후에도 이전 단계의 입력 내용을 확인할 수 있으며, 작업 시작 후 양식·주제·세부 내용·개인 저장값은 회색 읽기 전용으로 유지한다. 실제 문서의 최종 확인·수정은 출력된 한글 파일에서 한다.

1. 프로그램을 다시 실행하고 서울과학기술대학교의 **과제 문서 순차 작성**을 연다.
2. 첫 화면에서 **저장된 양식**을 선택한다. 원하는 양식이 없으면 **+ 새로운 양식 등록**에서 `.hwp` 파일을 고른다. 기본 제공 양식은 **기후부 기본 양식 추가**로 등록한다.
3. 새 양식은 파일 선택 후 AI가 분석하여 등록한다. 개인정보를 새로 입력하거나 저장하는 별도 화면은 없다. 새 양식은 `templates/<양식번호>/` 안에 분석 결과를 원본 사본과 함께 저장하며, 기존 기본 양식의 `guides/`는 유지한다. 기존 개인 프로필은 변경하지 않는다.
4. **작성 내용 입력 →**에서 **작성 주제**, **주제 세부 내용** 두 가지만 필수 입력한다. 목표·기간·예산·근거 등 알려진 사실이 있으면 세부 내용에 함께 적을 수 있지만 별도 필수 칸은 없다.
5. 선택한 양식에 정확히 연결되는 개인 탭의 저장값만 트리 표에 표시한다. 비어 있거나 연결되지 않은 값과 AI 본문 칸은 표시하지 않는다. 동일 개인 필드에 연결된 여러 문서 칸은 한 줄로 묶는다. 이름만 같은 서로 다른 필드는 임의로 합치지 않으며, 모호한 별칭은 자동 연결하지 않는다.
6. 필요하면 값을 더블클릭해 이번 문서에 넣을 값만 수정한다. 한 줄을 수정하면 연결된 모든 문서 칸에 적용된다. 개인 탭 원본 값은 바뀌지 않는다. 저장된 정보가 없어도 두 가지 작성 입력만으로 진행할 수 있다.
7. **AI 로그인**으로 연결한 뒤 **문서 작성 시작**을 누른다. 버튼 바로 위에 외부 전달 범위를 항상 안내하며 별도의 동의·검토 체크박스는 없다. 작업에는 `review_mode=final_output`, `preflight_reviewed=false`를 기록해 출력 전 검토를 완료한 것으로 잘못 기록하지 않는다.
8. 프로그램은 직접 입력값을 원본의 지정된 칸에 먼저 넣은 `기본정보_입력완료.hml` 사본을 만든다. 이후 큰 주제별 MD에서 현재 소주제 구역과 공통 요령을 읽어 AI에 전달한다. 새 작업은 소주제별 조사 질문 설정 → 공개 웹 검색·원문 확인 → 비교 분석·실행 방안 제안 → 근거를 포함한 본문 작성 순으로 진행한다. 직접 입력한 칸은 응답 대상에서 제외해 AI가 덮어쓰지 못한다.
9. 작성 중에는 진행 페이지에서 소주제와 진행률을 확인하거나 상단 단계·하단 이전/다음으로 입력 내용을 다시 확인한다. 이전 내용을 보는 동안에도 작업은 계속되며 상태 갱신이 화면을 강제로 이동시키지 않는다. 시작 전에는 진행 단계, 완료 전에는 완료 단계가 비활성화된다. 중단·오류 후 **이어서 작성**해도 원래 입력값과 잠금은 유지한다. 완료 페이지의 작업 요약과 **최종 출력본 한글 파일 열기** 버튼도 앞뒤 단계 이동과 함께 사용할 수 있다. 이후 한글에서 사실·수치·확인 필요 표시를 직접 검토하고 수정한다.

시작 시 입력값의 확인용 항목·그룹을 작업에 저장한다. 이전 작업을 다시 열면 현재 개인 탭의 값이 아니라 해당 작업의 주제·설명·입력값을 읽는다. 잠긴 표도 접기·펼치기, 열 너비 조절, 스크롤이 가능하다. 새 문서를 작성하려면 작성 창을 닫고 새로 열어 시작한다. 이 변경 전의 작업은 당시 그룹 기록이 없으므로 저장된 문서 위치와 값으로 확인 표를 구성한다.

외부 에이전트에 전달되는 내용은 사용자가 입력한 과제 정보, 작성요령 표의 공통·소주제별 내용과 입력 칸의 항목 설명,
앞에서 완료된 AI 초안이다. 직접 입력값은 별도로 전달하지 않으며, AI가 작성할 입력 칸만 요청한다. 단순히 참고 파일 경로를 적는 것은 파일 첨부가 아니다.
원문에 개인정보가 있으면 함께 전달될 수 있다는 점을 시작 버튼 위에 안내한다.
외부 전송은 ‘문서 작성’ 시 동의한 작업 범위에 한한다.

새 워크플로우는 자동 시험과 화면 구성요소 생성/입력 연결 시험으로 확인했다. 실제 로그인한 AI와 한글을 연결한 새 전체 실행은 아직 수행하지 않았다. 일반 양식의 쪽·표 배치 및 글자 크기는 보존하고 안내 표와 파란 주석을 정리한다. 기후부 전용 양식은 기존 확인된 입력 위치와 전용 출력 규칙을 유지한다.

개인별 정보·문서·프롬프트는 Git 저장 대상에서 제외했다. 설치형 실행 환경에서는 기존 사용자 데이터 경로 규칙을 따른다.

## 안전 장치

- 소주제 이름이 같아도 고유 번호와 원본 문단 위치가 다르다.
- 원본 파일 해시(파일이 바뀌었는지 확인하는 값)가 다르면 자동 입력을 차단한다.
- 에이전트 응답에는 허용한 필드 번호만 들어갈 수 있다. 문서 경로·명령어는 응답으로 실행하지 않는다.
- 응답의 소주제 번호, 필드 누락·추가, 길이, 제어 문자를 검사한다. 형식 오류만 최대 한 번 재요청한다.
- 연결 중단·한도 초과·한글 오류는 반복 호출하지 않고 실패 지점과 완료 내용을 남긴다.
- 조사 요청에서만 공식 제공 웹 검색·열람을 허용한다. 본문 작성 요청은 도구를 사용하지 않고 전달받은 조사 결과만 활용한다. 명령 실행·파일 변경·개인 연결 서비스 등 다른 도구는 작업별 설정으로 끄고, 허용하지 않은 도구 이벤트를 받으면 중단한다. 기존 로그인이나 PC 전역 설정은 변경하지 않는다.
- 명령 실행 환경은 읽기 전용이며 명령의 네트워크 접근도 차단한다. 공식 제공 웹 검색은 명령 실행 환경과 별도이므로 조사 단계에서만 활성화한다.
- API(Application Programming Interface·프로그램 연결 규약) 키 방식으로 자동 전환하지 않는다.
- 비밀번호·인증 토큰을 읽어 프로젝트 파일에 저장하거나 화면에 출력하지 않는다.
- 새 결과 파일만 만든다. 사용자가 열어둔 한글 문서를 닫거나 덮어쓰지 않는다.
- 각 소주제 완료 시 작성 중 문서(`작성중.hml`)에 반영한다. 마지막에 `.hwp` 파일을 저장한다.
- `자동검사.json`에는 예산 합계 검사·미확정 필드·원본 예시 표식 검사 결과가 남는다.
- 작성요령은 MD(Markdown·텍스트 문서 형식)에 보존하고, 출력 문서에서는 등록된 작성요령 표·파란 안내·기존 목차를 정리한다.
- 일정표는 `■`(진행), 빈칸(진행하지 않음), `?`(일정 미확정)만 허용한다.

## 자료조사와 분석 — 2026-09-15 추가

필수 입력은 기존의 작성 주제·주제 세부 내용 두 가지다. 공개 통계·정책·기술자료·유사 사례를 조사하고, 작성요령에 맞는 방법론·추진 단계·자원·위험 대응·평가 지표를 제안한다. 실제 실험·측정·기관 협의를 대신 수행하는 기능은 아니다. 계산이 필요한 경우 계산식·가정·단위를 명시하도록 요청하지만, 외부 코드 실행으로 계산을 검증하지는 않는다.

- 조사 결과는 출처가 연결된 사실, 아직 확정되지 않은 제안, 확인 필요 사항으로 구분한다. 사용자 실적·예산·협약을 조사 결과만으로 확정하지 않는다.
- 현재 소주제당 웹 작업은 24회 한도로 요청하며 한도 초과 이벤트를 감지하면 중단한다. 출처는 최대 12개다. 형식 오류는 한 번 재요청하므로 실패 후 재요청 시 추가 사용량이 발생할 수 있다.
- 웹 실행 이벤트가 없는 응답을 조사 완료로 취급하지 않는다. 다만 실행 기록과 출처 형식 검사는 출처 내용이 사실이거나 AI 해석이 정확하다는 보증은 아니다.
- `jobs/<작업번호>/research/`에 주제별 조사 결과와 웹 실행 기록, 근거 MD를 저장한다. 최종 `자료조사_근거.md`에 모아서 남기며, 확인 필요 사항은 `검토사항.md`에도 반영한다. 이미 끝낸 조사는 작업 재개 시 재사용한다.
- 진행 페이지에서 조사·검색·본문 작성·문서 반영 단계를 표시한다. 진행률은 문서 소주제 처리 기준이며 검색의 남은 시간 예측이 아니다.
- 공개 웹 조사에는 추가 시간과 연결된 계정 사용량이 필요하다. 과거 작업은 당시 조사 활성화 여부를 유지하며, 새 화면에서 시작하는 작업에 기본 적용한다.
- 개인 저장값은 조사·작성 프롬프트에 별도로 넣지 않는다. 사용자가 작성 주제·설명이나 원본 요령에 적은 비공개 내용은 AI에 전달될 수 있다. 공개 검색에는 개인식별정보·비공개 과제명을 쓰지 않도록 요청하지만 자동 비식별화를 보장하지 않는다.

공식 규격 확인: [App Server](https://learn.chatgpt.com/docs/app-server), [웹 검색과 명령 네트워크의 구분](https://learn.chatgpt.com/docs/web-search).

## 현재 한계 — 제출 완성 기능으로 표시하지 말 것

- 기후부 v3 양식: 소주제 33개, 입력 위치 1,698개. 33개 소주제 모두 자동 입력 위치를 연결했다.
- 기존 미연결 소주제의 일정표·기술기여도·실적·표준화·규제샌드박스·장비·기관현황·부담계획·별첨 일부를 추가 연결했다.
- ‘소주제 연결 완료’가 모든 표의 모든 칸 연결을 의미하지는 않는다. 일부 인력·세부 내역·추진체계 도형·조건부 별첨은 수동 작성 대상이다.
- 임의 양식은 AI가 주제·입력 역할을 판단하지만 무번호 제목·표 빈칸·교차 참조의 의미를 완벽히 분류하지는 못한다. 긴 문서는 나눠 분석하므로 멀리 떨어진 조건 연결이 누락될 수 있다. 원문 전체를 보존하고 불확실한 위치는 원본을 유지한다.
- 작성요령 표 안의 원문은 소주제에 나눠 보존한다. 의무·권고·조건부 규칙을 모두 구조화해서 자동 판정하는 기능은 아직 없다.
- 등록된 작성요령 표와 파란 안내는 정리하지만, 검은색 보조 문구·조건부 양식·일부 원본 빈칸과 예시는 남을 수 있다.
  불필요한 기관/연차/별첨을 임의로 삭제하지 않으며, 목차의 정확한 쪽번호도 자동 생성하지 않는다.
- 연결된 예산표의 합계를 검사한다. 숫자가 없으면 ‘자료 부족’이며 통과로 간주하지 않는다.
  실제 증빙과의 대조, 모든 비율·연차·인건비 계산, 모든 문서의 표 잘림 시각 검수는 자동 보장하지 않는다.
- 개인정보·실적·예산 근거가 없으면 ‘확인 필요’를 요구하지만, 이 지시가 사실성을 보증하지는 않는다.
