# 양식 등록 시 디자인·내용 분리 저장

적용일: 2026-09-28. 내부용 로컬 저장이며 추가 서버나 외부 AI 호출은 필요하지 않다.

## 등록과 출력

1. 기존 절차로 원본 한글과 원본 구조 데이터를 복사하고 소주제·작성요령 및 입력칸을 연결한다.
2. 원본 기준으로 제목 막대·숫자 배지·고정 항목을 보호하고 안전한 내용 입력 목적지를 정한다.
3. 양식 폴더에 버전별 `layout_<식별번호>.sqlite3`를 만든다. SQLite는 별도 서버가 필요 없는 파일형 데이터베이스다.
4. 데이터베이스 저장이 완료된 뒤 파일명·검증값·분류 개수를 `manifest.json`에 기록하고 등록을 공개한다.
   일반 등록, 기본 양식 추가, AI 분석 등록, 작성요령 중심 등록에 공통 적용한다.
5. 출력 작업에서는 원본·입력 연결 정보·데이터베이스 검증값을 확인하고 저장된 목적지를 읽어 작성한다.
   파일이 없거나 손상되었거나 입력 위치 버전이 다르면 임의로 추측하지 않고 중단한다.

원본 한글과 `source.hwpml`은 변경하지 않는다. 작업별 양식 복사본과 삭제 보관본에도 데이터베이스가 함께 들어간다.
사용자 확인으로 입력 연결이 바뀌면 새 데이터베이스 버전을 저장하고 이전 버전은 남긴다.
기존 등록 양식에는 강제 이관하지 않는다. 데이터베이스 없는 양식은 기존 보호 로직으로 출력할 수 있으며,
재등록/본문 작성 위치 다시 연결 시 새 등록본에 분리 저장이 적용된다.

## 데이터베이스 구조

| 테이블 | 저장 내용 |
| --- | --- |
| `metadata` | 원본·입력 연결 검증값, 분류기 버전, 등록 시각, 보호 문단 위치 |
| `design_layout` | 확인된 교체 입력칸과 작성요령 텍스트를 제외한 양식 구조. 글꼴·문단·쪽 설정·표·도형·고정 항목 유지 |
| `regions` | 문단별 고유 경로·표/셀 소속·분류·근거·원문·서식 참조 |
| `content_fields` | 필드 식별번호·소주제·원래 위치·실제 입력 위치·교체/뒤에 삽입/입력 차단 방식 |
| `tables` | 표 소속·중첩 관계·용도·표 구조 속성 |
| `cells` | 셀 소속·용도·크기·병합 등 속성 |

문단 분류는 `design`(디자인·고정 항목), `content`(교체 입력), `anchor`(원문 뒤 삽입),
`instruction`(작성요령), `preserve`(자동 입력 미지정·원본 유지)다.
디자인과 내용이 섞인 표는 `mixed`로 저장하며 내부 문단/셀별 구분을 따른다.
같은 제목이나 필드명이 반복되어도 문서 내 고유 위치로 구분한다.

이는 확정된 입력 위치를 보존하는 구조적 분리다. 모든 도형의 의미나 모든 미지정 빈칸을 자동으로
정확하게 이해한다고 보장하지 않는다. 미확정 부분은 원본 유지로 남기며 사용자 데이터를 생성하지 않는다.
