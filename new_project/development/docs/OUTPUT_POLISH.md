# 실제 출력본 서식 보정 (2026-09-22)

## 적용 경로

새 작성 작업의 개인 스냅샷에 `polished_output` 정책을 적용한다. 일반 AI 작성과
저장 응답 재사용이 동일한 `render_draft`를 거친다. 등록된 원본 양식과 응답 묶음은
변경하지 않는다. 기존 실행 중인 프로세스에는 재시작 후 새 작업부터 적용된다.

- 생성 본문만 원본 글꼴 계열을 유지하며 10~12pt의 정상 본문 크기로 보정한다.
  작은 빈 문단/제목에서 물려받은 3·5·8pt, 전체 굵게·기울임을 제거한다.
  제목·고정 표 라벨·디자인 띠의 글자 모양은 변경하지 않는다.
- 작성요령 표는 지우기 전 원문으로 식별한다. 실제 입력 필드 또는 보호된 제목이
  있으면 제거하지 않는다. 안내로 확정된 예시의 하위 표·도형만 정리한다.
- 예시 도형을 삭제한 연차 행은 높이도 줄인다. 연차 라벨과 입력 셀은 남긴다.
  응답에 없는 1·2차년도 내용을 새로 만들어 넣지 않는다.
- 지나치게 큰 단일 셀 포장 표를 풀어 내부 표가 여러 쪽에 걸쳐 이어지게 한다.
  법적 선언문은 문단 중간에 쪽이 나뉘지 않게 한다. 쪽 크기·여백은 원본과 같다.
- 요약문의 과제명·사업명을 앞 표지의 같은 의미 입력칸에 연결한다.
  연구 실적 표의 동명 항목은 제외하고, 모르는 사업명은 추측하지 않는다.
- 제목은 다음 문단과 묶고, 본문은 줄 간격과 문단 여백을 정리한다.
  정리 후 입력 위치를 다시 계산하여 실제 한글 읽기 결과와 대조한다.

## 표 원본 글꼴과 양방향 자간 보정 (2026-09-29)

- 생성된 표 입력값은 주변 본문 글꼴보다 해당 원본 표의 입력칸 글꼴을 우선한다.
  실제 값이 들어 있던 입력칸을 먼저 참고하고, 없으면 빈 입력칸의 원본 글꼴을
  사용한다. 같은 표 안의 입력값은 대표 글꼴로 통일한다. 명시된 표 글꼴 지시는
  여전히 최우선이며 고정 라벨·제목의 글꼴은 바꾸지 않는다.
- 새 문단의 자간은 원본을 기준으로 대략적인 어절 단위 줄 채움을 비교해 소폭
  넓히거나 줄인다. 짧은 한 줄은 억지로 늘리지 않으며, 원본보다 줄 수가 늘어나는
  후보는 제외한다. 새 보정은 -5%~+5% 안에서만 하고 그 범위 밖의 원본 설정은
  그대로 보존한다. 실제 줄 배치는
  한글 프로그램이 결정하므로 이 계산은 레이아웃 보증이 아닌 보수적인 추정이다.
- 등록 양식의 표 입력칸 228개 중 원본 입력 위치 226개에서 선택된 글꼴·크기가
  일치했다. 나머지 2개는 15pt 소제목 뒤에 새 글을 넣는 위치라 소제목 자체의
  글꼴 크기를 본문 입력 서식으로 취급하지 않았다.
  저장 응답을 넣은 HWPML 초안에서 자간 확대 66개, 축소 19개를 확인했다.
  기존 응답의 표 분량 경고 11개와 원본 예시 잔존 안내는 별개로 남아 있다.
- 한글 파일 변환 검증은 이 환경의 보안 모듈 등록 거부

## 긴 특수문자와 표 열 너비 (2026-09-29)

- 새로 쓴 문단에 URL·경로처럼 특수문자가 섞인 공백 없는 긴 덩어리가 한 줄 폭을
  넘을 때만 글자 단위 줄바꿈을 허용한다. 일반 문단의 어절 단위 줄바꿈은 유지하고,
  원문에 공백·하이픈·강제 줄바꿈 문자를 추가하지 않는다.
- 병합·중첩·그림이 없는 단순 표에서는 생성 내용이 셀 높이 기준으로 넘치고
  다른 열에 여유가 있을 때 열 폭을 조금 재배분한다. 표 전체 폭, 행·열 수,
  셀 테두리·병합 정보는 그대로 두며, 여유 열의 기존 내용이 한 줄이라도 더
  늘어나면 재배분하지 않는다. 받는 열은 원래 폭의 최대 30%, 주는 열은 20%
  이내에서만 움직인다.
- 현재 등록된 연구계획서와 저장 응답을 조합한 초안은 특수문자 긴 덩어리
  1문단에 글자 단위 줄바꿈이 적용되었다. 실제 양식의 긴 표 대부분은 병합 표거나
  다른 열에 여유가 없어 너비는 변경되지 않았고, 기존 표 분량 경고도 그대로다.
  단순 표 예제로는 폭 재배분과 전체 표 폭 보존을 검증했다.
- 실제 한글 파일에서의 최종 지면은 위 보안 모듈 오류로 확인하지 못했다.

## 가운데점 묶음과 자간 선택 순서 (2026-09-29)

- `연구·개발·검증`처럼 단어를 가운데점으로 묶은 생성 문장은 각 `·` 뒤에
  U+200B(폭 없는 공백)를 둬 해당 지점에서 줄을 넘길 수 있게 했다. 보이는 공백,
  하이픈, 강제 개행은 넣지 않는다. 원본 양식의 고정 문구는 변경하지 않는다.
- 응답·출력 위치 검사는 이 보이지 않는 줄바꿈 표식을 제외한 글자를 비교한다.
  표 분량 추정도 가운데점 뒤의 끊기 가능 지점을 반영한다.
- 자간 후보는 먼저 원본과 축소 범위를 비교한다. 축소로 줄 수가 줄면 그것을
  우선하고, 그렇지 않은데 줄의 길이 차이가 뚜렷할 때만 제한적으로 확대한다.
  짧은 한 줄을 채우려고 넓히지 않는다.
- 등록 양식에 저장 응답을 넣은 초안에서 가운데점 뒤의 보이지 않는 끊기 지점
  293곳, 자간 축소 19문단·확대 33문단을 확인했다. 기존 표 분량 경고 등
  출력 검사 안내 12건은 여전히 남아 있으며 실제 한글 지면은 미검증이다.
## 계산식의 한글 수식 개체 변환 (2026-09-29)

- 프로그램이 새로 작성한 본문·표에서 `P_net=P_gross-P_aux`처럼 아래첨자와 연산자가 포함된 명확한 계산식만 찾아, 한글 문서 형식의 편집 가능한 수식 개체로 바꾼다. 원본 양식의 고정 문구는 바꾸지 않는다.
- 식의 아래첨자는 한글 수식 스크립트의 `_{...}` 표기로 전달한다. 문장 중 식 앞뒤 내용과 입력 위치 확인에는 원래 식을 기준으로 사용한다.
- 수식 개체는 내부에서 줄바꿈할 수 없으므로, 표 셀 폭의 85%를 넘을 것으로 예상되면 일반 글자로 남겨 잘림 위험을 피한다. `Q=10` 같은 짧은 값 비교도 임의로 수식 개체로 바꾸지 않는다.
- 코드의 XML 구조·입력 위치 테스트는 통과했지만, 이 환경의 한글 보안 모듈 연결 문제 때문에 실제 `.hwp` 화면에서 수식 배치까지 검증한 것은 아니다.

## 전력 단위·화학 표기의 위첨자/아래첨자 (2026-09-29)

- AI가 새로 작성한 본문과 표에서 `MW_th`, `MW_e`, `kWth`, `MWe`의 `th/e`를 아래첨자로 표시한다. `H2`, `H2O`, `CO2`, `CH4`, `NH3`, `H2SO4` 등 지정된 분자식의 숫자도 아래첨자로, `m^2`, `m^3`, `/m2`, `/m3`의 지수는 위첨자로 표시한다.
- 문서에 이미 지정된 글꼴·크기·색을 복제한 한글 글자 모양의 `SUBSCRIPT`/`SUPERSCRIPT`를 사용한다. 변환하지 않은 원문 값을 작업 기록에 보존하고, 출력 위치 검사는 보이는 표기에 맞춰 진행한다.
- 원본 양식의 고정 문구, 사용자가 직접 입력한 값, 일반 약어와 확신할 수 없는 표기는 자동 변환하지 않는다. 분자식의 뜻이나 측정값을 계산하거나 만들어내지는 않는다.
