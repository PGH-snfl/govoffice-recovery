# 사용자 선택 영역 저장 및 데이터 표 관리

## 개인 탭의 새 버튼

- **선택 영역 → 개인정보 저장**: 연결된 한글 문서에서 항목 이름과 값을 함께 선택하고 누릅니다. 선택 영역의 후보를 표로 검토하고, 필요한 항목만 체크하여 저장합니다. 필드 경로와 값은 더블클릭해 수정할 수 있습니다. `연구자 > 성명`처럼 `>`로 하위 필드를 지정합니다.
- **데이터 표 관리**: 별도 창에서 대표 필드 → 하위 필드 → 저장된 값 → 기본 출력값을 확인합니다. 여러 값을 가진 필드 및 상위 필드는 세로 병합 셀로 표시합니다.

기존 프리셋의 `선택영역서식내보내기()`와 `HWPMLTableFieldAnalyzer`(표의 항목·값·병합 관계를 분석하는 기존 분석기)를 재사용합니다. 개인정보 가져오기에만 선택 셀 추출 옵션을 적용합니다. 셀 블록에서는 `InitScan(7, 255)`로 현재 선택 안의 텍스트를 읽고, 기존 내보내기 결과에서 그 내용과 현재 셀 주소에 대응하는 유일한 사각 범위만 남깁니다. 원래의 CELL 노드와 병합·문단 구조를 복사하며, 줄바꿈을 임의로 셀로 바꾼 임시 표는 만들지 않습니다.

개인정보 가져오기는 현재 선택만 사용합니다. 선택을 놓치면 같은 문서의 방금 전 드래그라도 대신 사용하지 않습니다. 현재 선택 모드·커서 위치가 유지되는지 확인합니다. 같은 글이 여러 곳에 있으면 현재 셀 주소도 대조하며, 유일한 범위를 입증할 수 없거나 병합 셀을 잘라야 하는 경우 중단합니다. 표 전체로 대체하거나 자동으로 전체 선택하지 않습니다. 기존 프리셋 저장의 동작은 바꾸지 않습니다. 셀 블록이 아닌 일반 텍스트 선택에는 UNICODE 내보내기 교차검사를 사용합니다.

2026-09-09 실제 선택 검증에서 HWPML2X·TEXT·UNICODE·HTML의 saveblock은 모두 선택 셀이 아닌 둘러싼 표 전체를 반환했습니다. 따라서 내보내기 두 종류끼리만 비교하는 이전 방식으로는 범위를 확인할 수 없었습니다. 반면 선택 전용 스캔은 파란 영역의 텍스트만 반환했고 선택 상태도 유지했습니다. 수정한 실제 추출 코드는 전체 151개 셀에서 선택한 28개 셀(0부터 세는 행 9~15, 열 0~30)만 남겼습니다. 분석 후보는 48개에서 12개로 줄었고, 선택 밖의 연구개발기간·연구개발비는 제외됐습니다. 원본 변경·개인정보 저장 없이 검증했습니다. 요약 기록은 `reports/dynamic_validation/current_selection_diagnostic.jsonl`에 있으며 원문 값은 기록하지 않습니다.

주의: 한글 자체의 서식 내보내기 결과에는 둘러싼 표가 포함됩니다. 프로그램은 이것을 그대로 분석하거나 저장하지 않고, 선택 전용 스캔으로 확정한 셀만 기존 분석기에 전달합니다. 동일한 내용으로 범위가 여러 개 성립하거나 중첩 표 등으로 구조를 확정할 수 없으면 임의 범위를 택하지 않습니다.

프리셋 분석과 동일한 등록 필드·별칭·기존 값 및 필드 경로 정리 규칙을 적용합니다. 개인정보 확인 목록은 저신뢰 후보도 개수 제한 없이 표시합니다. 프리셋 파일이나 프리셋 초안은 만들거나 변경하지 않고, 사용자가 확인한 필드와 값만 기존 개인정보 저장소에 저장합니다. 원본 한글 문서도 수정하지 않습니다.

## 관리 표 조작

- 필드 셀 우클릭: 이름 수정, 별칭 수정, 값 추가, 최상위로 이동, 필드 삭제.
- 값 셀 우클릭: 값 수정, 기본 출력값 지정, 값 삭제.
- 필드 셀을 다른 필드로 드래그: 해당 필드가 대상의 하위로 이동하며 모든 값·하위 필드가 함께 이동합니다.
- 값 셀을 다른 필드로 드래그: 해당 값만 이동합니다. 대상에 같은 값이 있으면 중복을 만들지 않습니다.
- 상단의 ‘최상위로 이동’ 영역에 필드를 드롭: 최상위 필드로 이동합니다.

수정·이동은 즉시 저장합니다. 삭제에는 확인 창이 나오며, 필드 삭제는 해당 필드와 모든 후손을 삭제합니다. 해당 필드를 사용하는 프리셋의 자동 입력에 영향을 줄 수 있습니다. 기본 이름·전화번호·이메일 필드는 기존 규칙에 따라 이름 변경·이동·필드 삭제를 제한하며, 값은 편집할 수 있습니다. 순환 계층이나 같은 부모 아래 이름·별칭 충돌은 오류로 안내하고 저장하지 않습니다.

## 기존 저장 구조 유지

기존 사용자 프로필 저장소(schema version 4)를 그대로 사용합니다. 각 필드는 `id`(고유 식별자), `대표필드명`, `별칭`, `값목록`, `기본값`, `상위필드id`를 갖습니다. 이름 변경·이동은 식별자를 유지하므로 기존 프리셋의 식별자 연결을 보존합니다. 기본값을 삭제하거나 다른 필드로 옮기면 남은 첫 값이 기본값이 됩니다. 값이 없으면 기본값도 비웁니다.

선택 영역 분석 초안은 프리셋 초안과 별도이며 15분 후 만료됩니다. 문서 또는 저장된 프로필이 바뀌면 재분석을 요구합니다. 관리 표도 마지막 조회 내용과 저장소를 비교해 오래된 화면의 변경을 차단합니다. 확인 항목 전체를 검증한 다음 기존 저장소의 임시 파일 교체 방식으로 한 번에 저장합니다.

문서 연결을 복원한 뒤 객체 식별자를 읽어, 복원 전 연결과 복원 후 문서 정보를 섞지 않습니다. 연결 확인에 실패하면 관리 문서와 활성 문서 식별자를 오류 기록에 남깁니다. 문서 본문이나 개인정보 값은 진단에 기록하지 않습니다.

화면은 백엔드 응답을 기다리는 동안에도 이벤트를 처리합니다. 대기 중에는 추가 요청을 차단하고 상태 확인·드래그 감지 타이머도 통신을 건너뛰어 응답이 섞이지 않도록 합니다. 기존 작업별 시간 제한은 유지합니다.

## 검증

시험용 저장소로 선택 저장, 반복 저장 중복 방지, 잘못된 입력의 일괄 취소, 만료·다른 문서·오래된 화면 차단, 값 수정·삭제·이동, 필드 계층 이동, 고유 식별자 보존을 검증합니다. `tests/profile_table_ui_probe.ps1`은 실제 화면 구성 함수와 WPF 이벤트를 메모리에서 실행해 병합 셀, 드롭, 우클릭 수정, 기본값 설정, 선택 저장을 검사합니다. 사용자 한글 문서에 대한 실제 마우스 조작 시험과는 구분됩니다.

`tests/backend_responsiveness_probe.ps1`은 실제 응답 대기 함수를 불러와 지연된 응답 중 화면 이벤트 처리, 중복 요청 차단, 시간 제한을 확인합니다. 기존 사용자 문서나 개인정보 저장소는 열지 않습니다.
