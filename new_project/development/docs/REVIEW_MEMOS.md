# 문서 작성의 확인 메모

새 AI 작성과 저장 응답 재사용에서 새로 만든 작업에 `review_memos` 정책을 적용한다. 이미 완료된 원본·결과 파일은 변경하지 않는다. 실행 중인 프로그램은 다시 시작한 뒤 새 출력을 만들어야 한다.

## 처리 방식

- AI가 작성한 본문은 요약하거나 삭제하지 않는다. 명시적인 확인 안내만 본문에서 분리한다.
- 빈칸·미정 표시뿐인 항목, 이름·연락처 같은 단순 사실 입력칸에는 메모를 만들지 않는다. 미확정 사실 칸은 빈칸으로 유지한다. 일반 문장 안의 `미확정` 같은 표현은 그대로 유지한다.
- 현재 응답의 필드별 검토 사유와 원래 AI 응답의 상세 사유를 사용한다. 과거 상세 사유는 현재에도 확인 표시가 남은 필드에만 연결한다. 사용자가 직접 입력한 값은 제외한다.
- 메모는 AI가 실제 작성한 본문의 검토 사유가 있을 때 해당 필드의 첫 문단에 연결한다. 표 안의 설명·계획도 본문으로 취급한다. 단순 빈칸 채우기 안내는 본문 검토 메모에서도 제외한다. 항목 이름·확인할 내용·확인 방법을 담으며, 모든 문장에 별도 메모를 붙이지는 않는다.
- 확인 방법은 기관·실적, 인력, 금액, 기간, 성능, 안전·인증 등 사유별 규칙으로 만든다. 별도 AI 호출이나 사실 검증을 수행하지 않는다. 사유가 없으면 실제 값·확정 여부를 확인하도록 안내한다.
- 새 작업의 `확인메모.json`에 연결 위치와 메모 내용을 함께 남긴다. 응답 묶음을 다시 내보낼 때도 원래 상세 응답을 보존한다.

## 한글 저장과 검사

소유한 별도 한글 인스턴스에서 실제 메모 원형을 생성하고, 같은 문서의 글자·문단 모양을 유지하면서 메모 필드를 연결한다. 한글의 `FieldId`는 메모 유형 코드이며, 독립 메모는 `InstId`와 순서로 구분한다. 원형 생성용 임시 본문은 최종 문서에 넣지 않는다.

메모 연결 전후와 실제 HWP 파일 재열기 후에 본문, 글자·문단 서식, 메모 내용, 연결 위치와 독립 식별번호를 비교한다. 기존 메모도 보존한다. 검증 실패를 숨기거나 메모 없는 출력을 성공으로 표시하지 않는다.
