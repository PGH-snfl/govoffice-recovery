# 내부 배포판 검증 결과

최종 파일: `dist/GovOffice-20260907-145019-913026.zip` (37,492,486 bytes).

- 별도 임시 한글/공백 경로에 ZIP을 풀고 실제 설치 스크립트를 실행했다.
- 설치된 자체 Python으로 분석 폴더와 무관한 작업 경로에서 백엔드 시작을 확인했다.
- 사용자 정보 저장 및 백엔드 재시작 후 값 유지, 설치 폴더 밖 저장을 확인했다.
- 배포 ZIP에 개발자의 사용자 프로필·즐겨찾기·프리셋이 포함되지 않은 것을 확인했다.
- 관련 자동 테스트 45개 통과, PowerShell 구문 검사 및 diff 공백 검사 통과.
- 실제 사용자 환경: Python 3.13.15, 한글 Office 2018, 보안 DLL x86.
- DLL 네이티브 로딩 및 IsAccessiblePath export 확인 통과.
- 배포판 DLL 경로를 공식 모듈 이름으로 등록해 RegisterModule, 문자 입력,
  임시 HWP 저장, 전용 Hwp.exe 프로세스 종료를 확인했다.
- 최종 실사 시작 전 기존 HWP 프로세스 5개, 생성한 테스트 PID 8996의 종료 확인.
  기존 문서는 제어하지 않았으며 테스트 종료 후 기존 레지스트리 경로를 복원했다.

발견 및 수정: 이 PC의 한글에서는 다른 등록 이름으로 RegisterModule=False가
발생했다. 공식 예제 이름 FilePathCheckerModuleExample 사용으로 실제 테스트를
통과했다. 실패 반환을 성공으로 취급하던 코드도 수정했다. 다른 별칭이 거부되는
한글 내부 원인까지 확정한 것은 아니다.

이 검증은 현재 PC에서 독립 설치 경로와 배포 DLL을 사용한 결과다. 물리적으로
다른 PC 및 다른 한글 버전에서는 아직 검증하지 않았다. 모든 복구 기능의 결과
동등성을 다시 검사한 것은 아니다. 새 PC에서 한글 설치/COM/DLL 조건을 검사하고
등록 실패를 구체적으로 안내한다. 64비트 한글은 대응 DLL이 필요하다.
