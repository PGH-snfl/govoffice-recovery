# 원본 실행파일 대 새 프로젝트 기능 비교

검증일: 2026-08-27

## 검증 범위

- 새 프로젝트에서 활성 버튼이 사용하는 고유 메서드 중 기존 `dynamic_exact` 72개를 제외한 359개를 추가 실행 비교했다.
- 원본 실행파일의 Python 3.13 마샬 코드와 복구 소스에 동일한 한글 문서·인자·이미지 파일을 입력했다.
- 각 항목은 별도 프로세스에서 실행했으며, 다음 항목 전에 해당 HWP 자동화 프로세스 종료를 확인했다.
- 비교 항목은 성공 여부, TEXT 본문, 정규화 HWPML 서식 구조, 반환값이다.

## 복구 내용

1. `광주광산표지`
   - 원인: 하위 기능 `광주광산결재선`이 원본 10열×5행 표 대신 간이 5열×2행 표로 대체돼 있었다.
   - 조치: 원본 Python 3.13 바이트코드를 디스어셈블해 셀 병합·이동 분기·테두리·문구를 소스로 복원했다.
   - 결과: 새 프로젝트 스냅샷에서도 본문·HWPML·반환값 완전 일치.

2. `마크다운응용`
   - 원인: 복구본 `마크다운()`과 `마크다운응용()` 사이의 무한 재귀로 새 한글 창 생성이 반복됐다.
   - 조치: 원본 마크다운 변환 본체로 연결하고, 현재 한글에서 `Style` 액션을 만들 수 없을 때 오류 대신 스타일만 건너뛰도록 안전 대체 경로를 추가했다.
   - 결과: 타임아웃 해소. 복구본은 오류 없이 종료한다. 원본은 같은 환경에서 `None.CreateSet` 오류가 남으므로 이 항목은 원본보다 호환성을 개선한 기능이다.

3. 이미지 HWPML 비교
   - 원인: HWP가 동일 이미지를 저장할 때 내부 BINDATA 컨테이너 해시를 새로 생성해 서식 불일치로 오판했다.
   - 조치: 그림 배치·크기·참조 구조는 계속 비교하되 파생 BINDATA 해시만 정규화했다.

4. 새 프로젝트 독립 실행
   - 원본 호환 마샬 4개를 `src/govoffice/runtime/recovered_hwp/bytecode/한컴오피스`에 분리 저장했다.
   - 새 프로젝트의 호환 계층은 작업공간 분석 폴더가 아니라 로컬 스냅샷을 우선 사용한다.

5. Hwp.exe 접근 위반 방지
   - 원인: `글자폰트바꾸기`·`글자폰트바꾸기간격`이 설치되지 않은 글꼴을 `AllReplace/FindCharShape`에 넘길 때 한글이 COM 예외가 아니라 프로세스 접근 위반으로 종료될 수 있었다.
   - 조치: 실행 전 Windows 글꼴 레지스트리를 확인하고 원본·대체 글꼴 중 하나라도 확인되지 않으면 AllReplace를 호출하지 않고 `False`로 안전 반환한다. 설치된 글꼴을 사용하는 환경에서만 원래 동작을 실행하며, 특수 검증 환경은 `GOVOFFICE_ALLOW_UNSAFE_FONT_REPLACE=1`로 명시적으로 선택한다.
   - 현재 PC의 `경기천년제목 Bold`, `HY헤드라인M`은 설치 확인이 되지 않아 경기 폰트 버튼은 Hwp를 건드리지 않고 종료한다. 이 조건에서 Hwp.exe 충돌 재발을 차단했다.

6. 실행 권한과 보안 모듈 경로
   - 냉간 상태에서 원본 실행파일과 복구 백엔드 모두 일반 권한으로 HWP COM 생성이 반환되지 않는 환경을 확인했다.
   - 새 GUI 런처는 관리자 권한으로 한 번 재실행해 원본과 같은 COM 실행 조건을 사용한다.
   - 보안 DLL 등록 스크립트 기본 경로를 실제 포함 파일인 `runtime/HwpAutomation/FilePathCheckerModuleExample.dll`로 수정했다.

## 공개 API 시그니처 보정 (2026-08-27)

생성 과정에서 빠진 원본의 trailing 기본 인자 188건을 Python 3.13 원본
클래스에서 추출해 `recovered_source/common/signature_defaults.py`에 분리
저장하고, 네 공개 클래스 로드 시 적용하도록 했다. 원본·복구 클래스의

`missing required positional argument`가 발생하지 않도록 하는 호환 계층이며,
각 메서드의 문서 출력 동등성 판정과는 별도로 관리한다.

최신 정적 커버리지 검사(`coverage_latest.json`)에서도 예상 1,511개 중
복구 1,511개, 누락 0개, 시그니처 불일치 0개, marshal 직접 의존 0개를
확인했다.

## 유효 입력 최종 재검증 (2026-08-27)

- `JSON에서변환`은 실제 한글 문서에 유효한 JSON을 삽입하고 전체 선택한
  조건에서 원본·복구본의 본문(19자), 정규화 HWPML(27,817자), 반환값을

  실제 한글 대조에서 본문(198자), 정규화 HWPML(52,509자), 반환값이 모두
  일치했다 (`current_recheck_random_v2.json`).
- `경남네모지정`, `남해기획네모`, `합천네모지정`은 검색 가능한 선택
  텍스트를 넣은 실제 한글 대조에서 본문·정규화 HWPML·반환값이 모두
  일치했다 (`current_recheck_text_v1.json`). 빈 문서에서 검색 결과가 없을
  때의 원본 오류 대신 복구본이 정상 반환하는 안전 경로는 별도 유지한다.
- `광주광산증감`은 1행 3열 숫자 표(10, 15)에서 실제 한글 대조한 결과
  본문·정규화 HWPML·반환값이 모두 일치했다
  (`current_recheck_gwangsan_v1.json`). 빈/문자열 셀에서 복구본이
  안전하게 안내하는 경로는 원본의 변환 오류와 구분해 유지한다.
- `가이드이자계산`은 원본의 표 셀 추출, 날짜 정렬, 잔액 누계, 10원 단위
  이자 절사, 최종 합계 및 `표:` 합성까지 소스 수준으로 복원했고, Style
  렌더러를 캡처 함수로 격리한 계산 대조에서 결과 문자열과 후속 호출이
  일치했다 (`current_recheck_guide_v1.json`). 현재 HWP의 Style 액션 부재로
  전체 렌더링은 `same_error`/호환성 개선으로 계속 분리한다.
- 따라서 현재 카탈로그는 `dynamic_exact` 339개,
  `same_error` 4개, `static_exact` 1,080개이며, 검증 보류 88개는
  `deferred_methods.json`에서 계속 분리한다.

## 제한 및 후속 확인

- 사용자가 제공한 화면의 `Hwp.exe` 메모리 접근 오류는 위 `AllReplace` 경로에서 재현된 유형이다. 복구본은 설치되지 않은 글꼴이면 해당 COM 호출을 차단한다.
- 글꼴이 실제로 설치된 PC에서는 관리자 권한으로 런처를 실행한 뒤 해당 버튼을 한 번 더 확인해야 한다. 설치된 글꼴 이름이 레지스트리에 확인될 때만 원본 AllReplace 동작을 허용한다.
