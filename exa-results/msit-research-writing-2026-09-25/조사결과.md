# 과기정통부 중심 연구개발 문서 작성 방식 조사

조사일: 2026-09-25  
목적: 연구자가 실제로 작성한 공개 자료에서 분야별·소주제별 설명 방식을 확인하고, 범정부오피스의 향후 문서 작성에 참고할 근거를 정리한다.

## 1. 이번에 실제로 확인한 범위

- IRIS(Integrated R&D Information System, 범부처통합연구지원시스템)를 출발점으로 공개 자료를 찾고 ScienceON의 국가 연구개발 보고서와 한국전자통신연구원 공개 원문으로 범위를 넓혔다.
- 26회 검색에서 결과 260개를 받았다. URL 일부 중복을 제거하면 243개다. 이것은 검색 결과 수이지 문서 전문을 읽은 수가 아니다.
- 대학·연구기관·기업이 작성한 보고서 40건의 공개 요약문 및 목차 등을 중심으로 비교했다. ScienceON 현재 부처 표기 기준 과학기술정보통신부 37건, 교육부·행정안전부·농촌진흥청 각 1건이다.
- 원문 PDF(Portable Document Format, 전자문서 형식) 3건의 주요 부분을 웹 텍스트로 추가 확인했다. 그중 1건은 위 40건과 중복이다.
- **공개적으로 확보한 신청 당시의 제출 계획서 완성본은 0건이다.** 최종·연차·단계 보고서, 공동기획연구를 제출용 계획서라고 부르지 않는다. 빈 양식과 공고의 RFP(Request for Proposal, 제안요청서)도 실제 작성 사례에 포함하지 않았다.
- 결과보고서에도 당초 목표, 연구내용, 연차 구분, 수행 방법, 다음 연도 계획이 포함되어 있어 내용 구성 비교에 활용했다. 신청서의 실제 분량 배분·평가점수·선정 이유는 이번 자료로 확인할 수 없다.
- 가장 오래된 중심 사례는 2016년 발행 자료다. 과거 시장 규모·기술 격차·세계 최고 수치를 현재 사실로 재사용하면 안 된다. 과거 소관 부처도 현재 메타데이터와 다를 수 있다.
- 40건 전문 전체 통독이나 원문 지면 디자인 검증을 한 조사는 아니다. 자료별 읽은 범위와 링크는 [사례별 분석](사례별_분석.md)에 남겼다.

## 2. 가장 중요한 관찰

이번 표본에서 구체적인 설명은 보통 다음 연결을 갖는다.

> 적용 대상과 현장의 문제 → 기존 방법으로 해결하지 못하는 지점 → 이번 연구의 구체적 목표 → 세부 해결 방법 → 비교·검증 조건 → 활용할 주체와 방법

이것은 모든 과제에 강제되는 공식 목차가 아니라, 읽은 사례들에서 추출한 작성 패턴이다. 분야에 따라 중간 연결은 달라진다.

- 기술개발형: 기존 기술 한계 → 개발할 구성요소 → 통합 → 성능·현장 검증.
- 기초연구형: 아직 설명되지 않는 현상 → 연구 질문·가설 → 관찰·개입 실험 → 기전 설명.
- 임상·바이오형: 미충족 문제 → 표적·환자군·검체 → 실험모델 → 유효성·비교 검증.
- 서비스·플랫폼형: 사용 현장의 문제 → 이용 흐름과 기능 → 기관·시스템 연계 → 실증·운영.
- 기획형: 환경 변화와 수요 → 사업 필요성 → 기술·기관별 역할 → 추진 구조. 실제 구현 성과와는 구분.

다음 절의 문장 예시는 원문 인용이 아니라 이러한 패턴을 설명하기 위해 작성한 재구성 예시다.

## 3. 소주제별로 무엇을 어떻게 쓰는가

### 3.1 연구개발 필요성

**무엇을 담나:** 대상의 현재 상태, 기존 해결 방식, 남은 한계, 그 한계가 초래하는 문제, 이번 연구가 필요한 이유.

**어떻게 푸나:** 국가 정책이나 시장 전망만 길게 쓰기보다 연구 대상의 구체적인 병목으로 좁힌다.

- 탄화규소 전력소자 사례는 에너지 효율 수요에서 실리콘 소자의 한계, 대체 소재의 특성, 국내 핵심 기술 필요성으로 전개한다.
- 암모니아 수소 사례는 기업의 사업 전환 수요를 기술 부족 문제로 바꾸고 열원·반응·공정 개발 필요성으로 나눈다.
- 비백금 촉매 사례는 비용 문제뿐 아니라 작은 전극에서의 성능이 실제 전지에서 유지되지 않는 문제를 제시한다.

**재구성 예시:** “기존 방식은 실험실 조건에서 성능을 보였으나 실제 운전 조건에서는 성능 저하가 발생한다. 따라서 저하 원인을 규명하고 운전 조건을 반영한 구조 개선을 검증할 필요가 있다.”

[탄화규소 소자](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO201900002135), [암모니아 수소](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202300004512), [비백금 촉매](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202100019409)

### 3.2 국내외 동향·기존 연구의 한계·차별성

**무엇을 담나:** 기존 기술이 해낸 일과 못 하는 일, 국내외 비교 대상, 이번 연구가 달리 다루는 조건.

**어떻게 푸나:** 논문이나 기업 이름 나열보다 ‘기존 방법 / 가능한 범위 / 남은 문제 / 제안 방법’을 대응시킨다.

- 지도 음영 자율주행은 정밀 지도가 없는 환경을 연구 범위로 설정한다.
- 설명 가능한 무선 자원 관리는 성능 최적화뿐 아니라 무선 환경 특성을 반영한 판단 설명 문제를 다룬다.
- 구조기반 신약개발은 보유한 예측 기술과 검증 경험을 앞으로 수행할 연구와 연결한다.

**주의:** “최초·최고·유일”은 별도 선행조사로 확인하지 않으면 쓰지 않는다. 기존 연구와 대상·조건이 다른데 숫자만 비교해서 우수하다고 판단하지 않는다.

[지도 음영 자율주행](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202200004830), [설명 가능한 무선 관리](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202400006707), [구조기반 신약개발](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202300014137)

### 3.3 최종목표·정량목표

**무엇을 담나:** 연구 종료 시 확보할 기술·모델·자료·장치, 적용 범위, 측정 가능한 판단 기준.

**어떻게 푸나:** 최종목표 한 문장 아래 구성요소 목표를 나누고, 수치의 의미를 조건과 함께 적는다.

- 이동통신 사례는 시스템, 기지국, 단말 등의 목표를 구별한다.
- 재구성로직 사례는 기존 구조 대비 성능·전력과 시뮬레이션·시제품 검증을 연결한다.
- 자율주행 시뮬레이션 사례는 소프트웨어뿐 아니라 자료집, 저작도구, 검증용 연결 장치까지 산출물로 명시한다.

작성용 지표 표의 권장 구조:

| 지표 | 기존 수준·비교 대상 | 제안 목표 | 측정 대상·조건 | 평가 방법 | 근거 |
|---|---|---|---|---|---|
| 실제 과제에 맞는 지표 | 확인된 값 | 사용자·연구자가 정할 값 | 환경·규모·대상 명시 | 시험·분석 절차 | 논문·시험자료 등 |

위 표는 조사에 기반한 제안이며 원문 서식을 그대로 복제한 것이 아니다. 목표값이 없으면 인공지능이 숫자를 임의로 확정하지 않게 해야 한다.

[밀리미터파 통신](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202100008583), [재구성로직](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202200012003), [주행 시뮬레이션](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202200004867)

### 3.4 세부 연구내용

**무엇을 담나:** 무엇을 입력으로 받아 어떤 처리를 하고 무엇을 산출하는지, 세부과제 간 관계.

**어떻게 푸나:** “플랫폼 개발”, “모델 고도화” 같은 큰 이름을 실제 작업으로 분해한다.

- 인공지능 신약 플랫폼: 유전체·표적 분석 → 구조 예측 → 후보물질 설계·최적화 → 실험 확인.
- 뇌신호 처리: 자료·모사 환경 → 잡음 제거 → 신호 분류 → 다중 전극 확장 → 발생 위치 해석.
- 양자컴퓨팅: 큐비트 제어 → 오류 관리 → 알고리즘 → 응용 서비스로 연구축을 연결.

**재구성 예시:** “세부과제 1에서 확보한 자료를 세부과제 2의 모형 학습에 사용하고, 세부과제 3에서 독립적인 검증 자료로 성능을 평가한다.”

[신약 플랫폼](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202300014118), [뇌신호 처리](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202100015969), [양자컴퓨팅](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202400003826)

### 3.5 연구방법·검증방법

**무엇을 담나:** 대상 선정, 비교군, 조건 변경, 측정 항목, 분석 방법, 통합·현장 검증.

**어떻게 푸나:** 방법 이름만 나열하지 않고 왜 그 방법이 연구 질문을 검증하는지 적는다.

- 오가노이드 사례는 환자 특성의 재현 여부를 먼저 확인한 뒤 집단별 약물 반응으로 나아간다.
- 산화물 반도체 사례는 공정 조건 변화와 성능·신뢰성 변화를 대응시킨다.
- 신경회로 기초연구는 분자 상호작용과 세포·동물 실험을 연결하여 기능을 설명한다.

**재구성 예시:** “조건 A와 조건 B를 제외한 나머지 조건은 동일하게 유지하여 차이를 비교한다. 효과가 확인된 조건은 더 복잡한 평가 환경에서 재검증한다.”

여기서 조건 A·B는 형식 설명용 자리표시자이며, 실제 계획에서는 무엇을 통제하고 비교하는지 구체화해야 한다.

[오가노이드](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202200014051), [산화물 소자](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202300000027), [신경회로 기전](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202300008144)

### 3.6 연차별·단계별 계획

**무엇을 담나:** 연도별 목표, 완료 조건, 다음 연도에 넘길 산출물, 확대되는 범위.

**어떻게 푸나:** ‘기초연구→개발→고도화’만 쓰지 않고 무엇이 실제로 늘어나거나 달라지는지 적는다.

| 사례 | 단계가 달라지는 기준 |
|---|---|
| 무선 자원 관리 | 단일 셀 → 다중 셀 간섭 → 대규모 분산 환경 |
| 배달로봇 | 이동 기반 → 균형·진동 제어 → 통합 제어 |
| 스마트 계약 보안 | 위협·분석 기반 → 보호·분석 도구 → 통합 모듈 |
| 양자컴퓨팅 | 큐비트 규모·제어, 오류 관리, 알고리즘과 서비스 범위 확대 |

전후 단계 사이에는 ‘앞 단계의 무엇을 받아 다음 단계에서 무엇을 확인하는지’가 있어야 한다는 것이 이번 비교의 해석이다.

[무선 자원 관리](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202400006707), [배달로봇](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202200014362), [스마트 계약 보안](https://scienceon.kisti.re.kr/srch/selectPORSrchReport.do?cn=TRKO202100009151)

### 3.7 추진체계·수행 역량

**무엇을 담나:** 연구기관별 담당 작업, 공동으로 만드는 결과, 자료·장비·현장 제공 역할.

**어떻게 푸나:** 기관 이름과 이력을 나열하는 데서 끝내지 않고 연구 작업과 연결한다.

지역산업 연계 원문에는 주관기관의 기술 개발, 지역 기업·대학의 조사·협업, 현장 자료 수집·사업화·실증 역할이 구분되어 있다. 복합인공지능 원문에도 대학별 연구 주제와 담당 내용이 연결된다. 다만 이번 자료만으로 협력의 우수성이나 선정 효과를 평가할 수는 없다.

[지역산업 연계 원문](https://ksp.etri.re.kr/ksp/report/file/36364.pdf), [복합인공지능 원문](https://ksp.etri.re.kr/ksp/report/file/36827.pdf)

### 3.8 활용방안·기대효과

**무엇을 담나:** 누가 무엇을 이용하는지, 연구 결과에서 실제 활용으로 넘어가기 위한 후속 작업.

**어떻게 푸나:** “산업 발전에 기여”에 앞서 이용할 기술·현장·제품을 적는다. 기초연구는 곧바로 제품 판매로 비약하지 않는다.

- 기초 신경회로 연구는 발병 원리 이해와 후속 치료 연구에 필요한 개념 제공을 구분한다.
- 그래핀 연구는 소재·구조의 성질을 센서·차폐·메모리 등 응용과 각각 연결한다.
- 예경보 플랫폼은 기존 체계 연동, 시범 운영, 개선을 서비스 활용 과정으로 다룬다.

### 3.9 이번 조사만으로 충분히 판단하지 못한 항목

연구비 세목별 산정의 적절성, 위험관리 계획의 상세 수준, 신청 양식별 배점 대응, 개인정보·연구윤리 심의 문구의 적정성은 비교 근거가 부족하다. 계획서의 법정·사업별 필수 항목은 해당 공고와 작성요령으로 별도 확인해야 한다. 공개 보고서의 서술 패턴을 현재 사업의 공식 작성 규칙으로 취급하지 않는다.

## 5. 문장·문단·표의 사용 방식

확인한 텍스트에는 짧은 제목 아래 개조식 문장을 겹쳐 쓰는 방식이 많다. 설명 문단과 목표·연차별 항목을 함께 사용한다. 다만 PDF 지면 이미지를 확인하지 못했으므로 도형·색상·페이지 배치의 우열은 분석하지 않았다.

이번 사례에서 도출한 작성 단위:

1. 소주제의 핵심 주장 한 문장.
2. 그 주장을 뒷받침할 현재 문제·선행 결과·대상 조건.
3. 수행할 구체 작업.
4. 작업 결과와 검증 방법.
5. 다음 작업이나 최종 활용과의 연결.

이 다섯 가지를 매 문단에 강제로 넣는다는 뜻은 아니다. 필요성에는 1·2, 연구내용에는 3·4, 추진계획에는 3·5가 중심이 된다.

- 여러 기술을 비교할 때: 비교 대상·한계·차이의 표.
- 여러 연도를 설명할 때: 목표·주요 작업·산출물의 표.
- 성능을 제시할 때: 지표·기준·목표·평가조건의 표.
- 기관이 여러 곳일 때: 역할·입력·산출물·연계 대상의 표.

위 표 설계는 작성 편의를 위한 제안이며, 심사에서 높은 평가를 받았다는 검증 결과는 아니다.

## 6. 우리 프로그램에서 참고할 수 있는 방식 — 구현이 아닌 조사 제안

이번 조사로 보면 모든 소주제에 같은 ‘공통 작성요령’을 전달하는 것만으로는 내용이 구체화되기 어렵다. 다음 세 층을 구분하는 편이 적합하다.

1. **양식의 실제 작성요령:** 사용자가 등록한 문서에서 추출한 소주제와 바로 아래의 지시. 임의의 공통 지침으로 바꾸지 않는다.
2. **분야·소주제별 전개 패턴:** 이번 조사처럼 해당 항목에서 무엇을 어떤 순서로 설명하는지 정리한 참고 정보.
3. **해당 과제의 사실:** 사용자 연구내용, 실제 선행 성과, 사용 가능한 자료·장비, 참여기관, 기간, 목표값, 근거 출처.

예를 들어 ‘연구개발 방법’이라도 수소 과제에는 촉매 조성·반응 조건·안정성 시험을, 의료 인공지능 과제에는 환자 집단·자료·비교 모형·평가 방법을 중심으로 문장을 구성해야 한다.

AI(Artificial Intelligence, 인공지능)에 전달할 항목의 예:

| 항목 | 내용 |
|---|---|
| 소주제 원문 | 양식에서 읽은 제목 그대로 |
| 해당 작성요령 | 그 소주제에 붙은 지시 그대로 |
| 과제 사실 | 사용자가 제공하거나 출처로 확인된 내용 |
| 분야별 참고 구조 | 필요성·목표·방법 등 해당하는 전개 패턴 |
| 조사 근거 | 출처, 연도, 적용 조건 |
| 부족한 정보 | 연구자가 결정해야 할 수치·역할·일정 |
| 작성 결과 상태 | 확정 사실 / 계획 / 확인 필요를 내부적으로 구분 |

이 구조를 따르면 참고 문서의 문장을 베끼는 대신 설명 방식을 활용할 수 있다. 목표값·검체 수·연구 실적·협약기관처럼 사실 확인이 필요한 항목을 임의 생성해서는 안 된다. 부족한 정보는 작성 중 한 번에 검토할 목록으로 모을 수 있다.

이번 작업에서는 프로그램 동작을 수정하지 않았다. 위 내용은 조사에 기반한 설계 제안이다.
